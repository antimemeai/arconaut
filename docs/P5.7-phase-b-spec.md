## 1. Scope

Phase B builds the core tools on top of the Phase A foundation. It delivers:

1. **Neovim-native tools:** `ReadNV`, `WriteNV`, `EditNV`, `QueryAST`
2. **Structured Shell Log:** OSC 633 grammar + log format
3. **Shell tools:** `RTermRead`, `RTermWrite`
4. **Remote tools:** `RemoteRead`, `RemoteWrite`, `RemotePatch`, `RemoteSearch`, `RemoteExecute` over SSH

**Out of scope:** BufferManager, Heuristic Engine, Beat, Vectored, Neurotic, Tempo modes beyond Metronome.

## 2. Tool Schemas

All tools implement `arconaut_core::Tool`. They are registered in `arconaut_reactor::ToolRegistry`.

### 2.1 ReadNV

```rust
pub struct ReadNvTool {
    nvim: Arc<Mutex<NvimRuntime>>,
}

impl Tool for ReadNvTool {
    fn name(&self) -> &str { "ReadNV" }
    fn description(&self) -> &str { "Read a file through the headless neovim runtime." }
    fn parameters(&self) -> &Value {
        json!({
            "type": "object",
            "properties": {
                "path": { "type": "string", "description": "Relative or absolute file path" },
                "offset": { "type": "integer", "description": "Line offset (0-based, inclusive)", "default": 0 },
                "limit": { "type": "integer", "description": "Max lines to read", "default": 200 }
            },
            "required": ["path"]
        })
    }

    async fn call(&self, args: Value) -> Result<ToolResult, ToolError> {
        // 1. Resolve path relative to cwd.
        // 2. Call nvim.command(&format!("edit {}", path_escaped)).
        // 3. Get buffer handle via nvim.get_current_buf().
        // 4. Get lines via nvim.buf_get_lines(buf, offset, offset + limit, false).
        // 5. Return ToolResult::Success with formatted output.
    }
}
```

**Output format:**
```
<file path="src/lib.rs" lines="0-49" total="150">
... contents ...
</file>
```

**Errors:**
- `NotFound` — file does not exist
- `PermissionDenied` — cannot read
- `NvimError` — RPC failure

## 3. Neovim Interface Extensions

### 3.1 Required Lua Bridge

`arconaut.lua` must expose:

```lua
-- Run a tree-sitter query on the current buffer.
-- Returns a list of { type, name, range, text } tables.

-- Returns { replaced = true/false, range = {...} }.
function ArconautEditByQuery(query_string, replacement)
```

Loaded on `NvimRuntime::spawn()` via `--cmd "luafile /path/to/arconaut.lua"`.

## 4. Structured Shell Log

### 4.1 Grammar (Phase B)

```
<shell-log>     ::= <entry>*
<entry>         ::= <command-entry> | <output-entry> | <error-entry>
<command-entry> ::= "CMD" <timestamp> <cwd> <duration?> <command-text> "\n"
<output-entry>  ::= "OUT" <timestamp> <lines>
<error-entry>   ::= "ERR" <timestamp> <lines>
<timestamp>     ::= ISO-8601
<cwd>           ::= quoted-path
<duration>      ::= millis-as-int
<command-text>  ::= rest-of-line
<lines>         ::= <line>* "END" "\n"
```

Example:
```
CMD 2026-06-07T12:00:00Z /Users/patrickbeam/projects/arconaut 1542 cargo test
OUT 2026-06-07T12:00:02Z
running 235 tests
235 passed, 1 skipped
END
ERR 2026-06-07T12:00:02Z
END
```

### 4.2 `ShellLog` Type

```rust
pub struct ShellLog {
    entries: Vec<LogEntry>,
}

pub enum LogEntry {
    Command { timestamp: DateTime<Utc>, cwd: PathBuf, duration: Option<Duration>, command: String },
    Output { timestamp: DateTime<Utc>, lines: Vec<String> },
    Error { timestamp: DateTime<Utc>, lines: Vec<String> },
}
```

### 4.3 OSC 633 Parser (Phase B)

```rust
impl Osc633Parser {
    /// Parse a stream of bytes containing OSC 633 sequences.
    /// Returns (remaining_plaintext, Vec<Osc633Event>).
```

```rust
pub struct SshSession {
    host: String,
    control_path: PathBuf,

impl SshSession {
```

## 6. Conformance Specification (Phase B TCK)

### 6.1 Implementation Relation

For each tool, "correct" means:
- The tool's JSON schema matches the spec exactly.
- The tool's `call()` produces the specified output format for valid inputs.
- The tool returns the specified error variant for invalid inputs.
- Tool registration in `ToolRegistry` succeeds and `descriptors()` includes the tool.

### 6.2 Fault Model

| Fault | Description | Detection |
|---|---|---|
| F1 | Tool schema drift (missing required field) | Schema validation test |
| F2 | ReadNV returns wrong file content | Roundtrip test: write → read |
| F3 | EditNV fails to replace matching node | Query-before/after test |
| F4 | QueryAST returns malformed JSON | JSON parse test |
| F5 | RTermRead returns stale output | Append + read test |
| F6 | Shell log parser drops entries | Parse known input test |
| F7 | SSH exec returns local instead of remote output | Host-specific marker test |
| F8 | Tool not registered | Registry enumeration test |

### 6.3 Oracles

**O1 — Roundtrip oracle:**
`WriteNV(path, content)` followed by `ReadNV(path)` returns `content`.

**O2 — Edit verification oracle:**
After `EditNV(path, query, replacement)`, `ReadNV(path)` contains `replacement` at the matched location.

**O3 — Query completeness oracle:**
`QueryAST(path, "(function_item) @fn")` returns one entry for every top-level function in the file.

**O4 — Shell log append oracle:**
After `RTermWrite("echo marker")` + `RTermRead(10)`, the log ends with `"marker"`.

**O5 — Remote isolation oracle:**
`RemoteExecute(host, "hostname")` returns the remote hostname, not the local one.
