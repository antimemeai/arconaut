## 1. Scope

Phase A establishes the architectural foundation for all subsequent P5.7 work. It consists of three parallel tracks:

1. **Crate Split:** Create `arconaut_pilot` and `arconaut_reactor` crates with clean trait boundaries.
2. **Neovim RPC:** Prototype `nvim --embed` communication via `rmp-rpc`.
3. **Brush Integration:** Hello-world command execution via `brush-core` with OSC 633 capture.

**Out of scope for Phase A:** Tool implementations (ReadNV, EditNV, etc.), BufferManager, Heuristic Engine, Beat injection, Structured Shell Log grammar, Remote tools, Vectored, Neurotic, Tempo modes beyond Metronome.

### 2.2 Crate Boundary: `arconaut-pilot`

**Responsibility:** Megan's reasoning loop. Pure LLM interaction. No environmental management.

**Modules:**
```
arconaut-pilot/src/
├── lib.rs              # Crate root: exports Soul, Tempo, Deduplicator
├── soul.rs             # Soul v2: turn execution, provider interaction
├── tempo.rs            # Tempo state machine: Metronome / Tuned / MainCharacter / Evolving
├── dedup.rs            # Deduplicator: per-turn tool call deduplication
└── types.rs            # Pilot-specific types: TurnRequest, TurnResponse, StepResult
```

**Public API:**

```rust
/// The pilot's view of what the reactor assembles.
pub struct TurnRequest {
    pub context: Vec<Message>,       // Full conversation history + system + injected state
    pub available_tools: Vec<ToolDescriptor>,
    pub tempo: Tempo,
}

/// The pilot's response after one provider call.
pub struct TurnResponse {
    pub message: Message,            // Assistant message (may contain tool_call_requests)
    pub stop_reason: StopReason,     // Completed, MaxStepsReached, ChurnDetected, ProviderError
    pub token_usage: TokenUsage,
}

/// Reasons a turn step terminated.
pub enum StopReason {
    Completed,           // No tool calls in response
    ToolCallsRequested,  // Response contains tool_call_requests (reactor should execute & re-call)
    MaxStepsReached,
    ChurnDetected,
    ProviderError(String),
}

/// Soul v2 trait. The reactor drives the loop; the Soul is pure provider interaction.
#[async_trait]
pub trait Soul: Send + Sync {
    /// Execute one provider call. Does NOT execute tools.
    /// The reactor is responsible for the tool-execution loop.
    async fn execute(&mut self, request: TurnRequest) -> Result<TurnResponse, SoulError>;

    /// Signal that the reactor has executed tool results and wants to continue the turn.
    /// The Soul appends tool results to its internal context and calls the provider again.
    async fn continue_turn(&mut self, tool_results: Vec<ToolResult>) -> Result<TurnResponse, SoulError>;
}

/// Concrete implementation.
pub struct DefaultSoul {
    provider: Box<dyn ChatProvider>,
    config: SoulConfig,
}

impl DefaultSoul {
    pub fn new(provider: Box<dyn ChatProvider>, config: SoulConfig) -> Self;
}

#[async_trait]
impl Soul for DefaultSoul {
    async fn execute(&mut self, request: TurnRequest) -> Result<TurnResponse, SoulError>;
    async fn continue_turn(&mut self, tool_results: Vec<ToolResult>) -> Result<TurnResponse, SoulError>;
}

/// Tempo state machine.
pub enum Tempo {
    Metronome,
    Tuned { ratio: u8 },        // tool:chat ratio, 1:1 to 10:1
    MainCharacter,              // 50:1+, checkpoints only
    Evolving,                   // auto-varying — later phase
}

impl Tempo {
    /// Whether the Soul may issue parallel tool calls.
    pub fn allows_parallel_tools(&self) -> bool;
    /// Narration density: full, summary, checkpoint-only.
    pub fn narration_level(&self) -> NarrationLevel;
}

/// Per-turn deduplication.
pub struct Deduplicator;

impl Deduplicator {
    pub fn new() -> Self;
    /// Clear at the start of each turn.
    pub fn clear(&mut self);
    /// Check if this tool call was already made this turn.
    pub fn is_duplicate(&self, tool_name: &str, args: &serde_json::Value) -> bool;
    /// Record a tool call.
    pub fn record(&mut self, tool_name: &str, args: &serde_json::Value);
    /// Consecutive duplicate count (for churn detection).
    pub fn consecutive_count(&self) -> usize;
}
```

**Dependencies:** `arconaut-core`, `async-trait`, `serde`, `serde_json`.

**Invariant:** `arconaut-pilot` MUST NOT depend on `arconaut-reactor`.

**Public API:**

```rust
/// The central orchestrator. Owns the turn loop.
pub struct ArconautLogic {
    context_assembler: ContextAssembler,
    tool_registry: ToolRegistry,
    heuristic_engine: HeuristicEngine,
    audit: AuditEmitter,
    config: ReactorConfig,
}

impl ArconautLogic {
    pub fn new(config: ReactorConfig) -> Self;

    /// Run one full turn: assemble → soul.execute → execute tools → loop → audit.
    pub async fn run_turn<S: Soul>(
        &mut self,
        soul: &mut S,
        user_input: &str,
    ) -> Result<TurnOutput, ReactorError>;
}

/// Output of a complete turn (after all tool-call loops).
pub struct TurnOutput {
    pub final_message: Message,
    pub steps_taken: usize,
    pub completed: bool,
    pub stop_reason: StopReason,
    pub audit_events: Vec<AuditEvent>,
}

/// ContextAssembler builds the TurnRequest that the Soul receives.
pub struct ContextAssembler {
    history: Vec<Message>,
    system_prompt: String,
    beat: BeatState,
    // working_set, vectored_results, etc. — stubs in Phase A
}

impl ContextAssembler {
    /// Build a TurnRequest for the Soul.
    pub fn assemble(&self, user_input: &str, tempo: Tempo) -> TurnRequest;
    /// Append a message to history.
    pub fn append(&mut self, message: Message);
    /// Inject Beat state.
    pub fn inject_beat(&mut self, beat: BeatState);
}

/// Beat state injected into context.
pub struct BeatState {
    pub base_dir: PathBuf,
    pub work_dir: PathBuf,
    pub session_elapsed: Duration,
    pub active_phase: String,
    pub last_tool: Option<String>,
    pub last_file: Option<PathBuf>,
    pub compactions: usize,
    pub context_used: (usize, usize), // (used, total)
    pub working_set: Vec<PathBuf>,
    pub last_test_run: Option<String>,
}

/// ToolRegistry owns all tool implementations.
pub struct ToolRegistry {
    tools: HashMap<String, Box<dyn Tool>>,
    sequence: u64, // schema version sequence number
}

impl ToolRegistry {
    pub fn new() -> Self;
    pub fn register(&mut self, tool: Box<dyn Tool>);
    pub async fn execute(&self, name: &str, args: serde_json::Value) -> ToolResult;
    pub fn descriptors(&self) -> Vec<ToolDescriptor>;
    pub fn schema_sequence(&self) -> u64;
}

/// Tier 1 heuristic engine.
pub struct HeuristicEngine {
    state: HeuristicState,
    config: HeuristicConfig,
}

impl HeuristicEngine {
    pub fn new(config: HeuristicConfig) -> Self;
    /// Evaluate one turn step. Returns any interventions.
    pub fn evaluate(&mut self, event: TurnEvent) -> Vec<Intervention>;
}

/// Events fed to the heuristic engine.
pub enum TurnEvent {
    ToolCall { name: String, args: serde_json::Value, result: ToolResult },
    ProviderResponse { message: Message, token_usage: TokenUsage },
    Compaction,
    TempoChange { from: Tempo, to: Tempo },
}

/// Interventions the heuristic engine can request.
pub enum Intervention {
    Nudge(String),       // Inject a system message
    Warning(String),     // Inject a stronger system message
    Pause(String),       // Halt the turn, require operator action
    BeatTaken,           // Trigger Beat Taken injection
}
```

## 3. Soul v2 State Machine

### 3.1 Turn Loop (reactor-owned)

```
ArconautLogic::run_turn(soul, user_input)
  │
  ├── ContextAssembler::assemble(user_input, tempo) → TurnRequest
  │
  ├── soul.execute(turn_request) → TurnResponse
  │     │
  │     ├── Build ChatRequest from TurnRequest
  │     ├── provider.chat(chat_request) → ChatResponse
  │     └── Return TurnResponse
  │
  ├── Match TurnResponse.stop_reason:
  │
  │   Completed → TurnOutput { final_message, completed: true }
  │
  │   ToolCallsRequested →
  │     │
  │     ├── Deduplicator::is_duplicate? Skip if yes.
  │     ├── ToolRegistry::execute(tool_call) → ToolResult
  │     ├── HeuristicEngine::evaluate(ToolCall event)
  │     ├── AuditEmitter::emit(tool_call, result)
  │     │
  │     ├── If interventions → inject into context
  │     │
  │     └── soul.continue_turn(tool_results) → TurnResponse
  │         (loop back to Match)
  │
  │   MaxStepsReached / ChurnDetected / ProviderError →
  │     └── TurnOutput { final_message, completed: false }
  │
  ├── HeuristicEngine::evaluate(ProviderResponse event)
  ├── AuditEmitter::emit(turn_summary)
  └── Return TurnOutput
```

### 3.2 Invariants

- **I1:** The Soul never executes tools directly. It only makes provider calls.
- **I2:** The reactor never makes provider calls directly. It only drives the Soul.
- **I3:** `Deduplicator` is reset at the start of each `run_turn` call.
- **I4:** `HeuristicEngine` state persists across turns within a session.
- **I5:** The Soul's internal context is append-only during a single `run_turn`.

## 6. Conformance Specification (Phase A TCK)

### 6.1 Implementation Relation

For each subsystem, "correct" is defined as:

**Crate Boundary (pilot ↔ reactor):**
- The pilot crate compiles and its public API is callable.
- The reactor crate compiles and depends on pilot.
- The agent crate wires both together and runs a minimal turn.

**Soul v2:**
- `DefaultSoul::execute()` returns a `TurnResponse` within 30s for a valid provider.
- `DefaultSoul::continue_turn()` appends tool results and makes a second provider call.
- The Soul never calls `Tool::call()` directly.

**Neovim RPC:**
- `NvimRuntime::spawn()` succeeds within 200ms.
- `command("echo 'hello'")` returns `"hello"`.
- `eval("1 + 1")` returns integer `2`.
- `shutdown()` terminates the nvim process cleanly (exit code 0).

**Brush:**
- `BrushRuntime::new()` succeeds.
- `exec("echo hello")` returns `exit_code: 0`, `stdout: "hello\n"`, `stderr: ""`.
- `exec("exit 42")` returns `exit_code: 42`.

### 6.2 Fault Model

| Fault Class | Description | Detection |
|---|---|---|
| F1 | Crate dependency cycle (pilot → reactor) | Compile-time: `cargo check` fails |
| F2 | Soul executes tools directly | Code review + unit test |
| F3 | Reactor makes provider calls | Code review + unit test |
| F4 | Nvim spawn timeout (>200ms) | Integration test with timeout |
| F5 | Nvim RPC returns error instead of result | Integration test: assert Ok |
| F6 | Brush exec returns wrong exit code | Unit test: assert_eq!(exit_code, expected) |
| F7 | Brush exec hangs | Integration test with timeout |
| F8 | Deduplicator fails to clear between turns | Property test: two identical calls in different turns are not duplicates |

### 6.3 Oracles

**O1 — Soul purity oracle:**
Given a `MockProvider` that returns a fixed `ChatResponse`, `DefaultSoul::execute()` produces the same `TurnResponse` every time. No filesystem, network, or shell side effects.

**O2 — Turn loop completeness oracle:**
Given a `MockProvider` that requests a tool call on the first response and returns text on the second, `ArconautLogic::run_turn()` executes exactly one tool call and returns the second response.

**O3 — Neovim roundtrip oracle:**
After `command("let g:test = 42")`, `eval("g:test")` returns `42`.

**O4 — Brush exit code oracle:**
For any shell command `cmd`, `exec(cmd).exit_code` equals the POSIX exit status of `cmd`.

### 6.4 Test Adequacy

- **Spec coverage:** Every public function in `arconaut-pilot` and `arconaut-reactor` has at least one test.
- **Code coverage:** >80% line coverage for new crates.
- **Oracle coverage:** At least one test per oracle (O1–O4).
