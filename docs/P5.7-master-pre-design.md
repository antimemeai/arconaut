# P5.7 Master Pre-Design Document

**Project:** arconaut — CLI Coding Agent ("Megan")  
**Phase:** 5.7 — Embedded Shell & Agent Architecture  
**Status:** Pre-design (foundation for formal specs)  
**Date:** 2026-06-07  

---

## 1. Executive Summary

Phase 5.7 rearchitects arconaut from a naive string-replacement agent into a **structure-native coding companion** where Megan (the pilot model) never does mechanical work that a traditional program handles better. Every file operation routes through a headless neovim instance via MessagePack RPC; every shell command executes inside a persistent `brush-core` embedded shell with OSC 633-structured output; and a predictive BufferManager warms files before Megan asks. The Soul—the LLM turn loop in `soul.rs` (line 127)—is stripped of environmental management and refocused on pure reasoning, while a new Arconaut Logic Layer handles context assembly, ambient heuristic detection, and automatic injection of Beat state readouts and Vectored embedding queries. Tempo governance (Metronone/Tuned/MainCharacter/Evolving) modulates narration density and tool-batching behavior.

This design is quantitatively grounded: AgentDiet shows coding-agent trajectories average **48.4K tokens across 40 steps**, reaching **1M tokens per issue**, with **39.9–59.7%** of those tokens being recoverable waste; LLMLingua achieves **up to 20× prompt compression**; CodeStruct's AST-based action spaces cut token consumption **12–38%** and inference cost **33%**; and StreamingLLM sustains **4M+ tokens** at **22.2× speedup** via attention-sink KV cache management. We translate these findings into a tiered token budget where audit logs live outside the context window, working-set summaries replace full file reads, and structured shell logs replace raw TTY output.

## 2. Core Principles

### 2.1 "Bicycles for Megan's Mind"

Megan manipulates meaning; the environment handles representation. Neovim resolves "the function named `refresh_token`" structurally. Extmarks survive line-number drift automatically. The BufferManager predicts the next file before she asks. Megan should never parse raw terminal output, count lines, or match exact strings.

### 2.2 Soul vs. Arconaut — Separation of Concerns

| **Soul (The Pilot)** | **Arconaut Logic (The Physical Plant)** |
|---|---|
| Turn execution — LLM reasoning loop | Injector management — what goes into context |
| Tool calling decisions | Prompt injection — Beat, Vectored results |
| Tempo management | Runtime orchestration — neovim, brush, buffer manager |
| Response generation | Ambient tool orchestration — Vectored, Neurotic auto-fire |
| Checkpoint decisions | Heuristic detection — flailing, drift, struggle |

The Soul is Megan. She reasons, decides, calls tools. Arconaut is the ship: it maintains state, injects context, runs ambient systems, coordinates runtimes. This boundary is enforceable at the crate boundary: `arconaut_pilot` contains the Soul; `arconaut_reactor` contains everything else.

### 2.3 Tempo Governance

Tempo is not a user preference — it is a **contract** that changes how the Soul operates:

| Tempo | Tool:Chat Ratio | Narration | Use Case |
|-------|-----------------|-----------|----------|
| **Metronome** | 1:1 | Every tool call narrated | Discussion, exploration |
| **Tuned** | 1:1 → 10:1 | Summary only after batch | Implementation, debugging |
| **MainCharacter** | 50:1+ | Checkpoints only | Long-running spec execution |
| **Evolving** | Auto-varying | Adaptive | Deep water — later phase |

The Soul requests mode changes; Arconaut auto-detects them (e.g., 500-line spec paste → suggest MainCharacter). The operator retains override authority via `/tempo` slash commands. **Exit from Tuned mode is operator-only for now.**

## 3. Subsystem Architecture

### 3.1 Neovim Headless (CodeRuntime)

**What it is.** An `nvim --embed` child process spawned by `arconaut-agent`, communicating via `rmp-rpc` MessagePack RPC. A custom `arconaut.lua` module exposes tree-sitter CSTs, extmarks, undo history, and multi-buffer transactions to the agent. This is the sole code-editing runtime — no direct file I/O by the agent.

**What it replaces.** The current `ReadTool`, `WriteTool`, and `EditTool` in `tools.rs` (lines 14–261), which perform naive string-based file operations with ~50% failure rates per the structural editing research.

**Key design decisions:**
- **No optional backend.** `read`, `write`, `edit` are deleted. All file manipulation is neovim-native.
- **Extmarks for stable references.** Megan references semantic labels, not line numbers. Labels survive all edits automatically.
- **Extmark persistence.** Runtime extmarks are ephemeral. Source of truth is `.arconaut/marks.json`: a versioned JSON intent file with client-generated UUIDs, contextual anchoring (`context_before` / `context_after`), and fuzzy re-anchoring on buffer load. Write-through with 5s debounce; flush on `SIGTERM` / `nvim_detach`.
- **AST queries over string matching.** `QueryAST` returns exact tree-sitter nodes. `EditNV` accepts tree-sitter query selectors.
- **Undo/redo as experimentation primitive.** Multi-buffer transactions support speculative editing.
- **Startup cost budget.** If `nvim --embed` startup exceeds 200ms, keep the process warm across turns.
- **nvim-rs replacement commitment.** `nvim-rs` is LGPL-3.0 — a license blocker. We use `rmp-rpc` as an intermediate binding and commit to a ground-up MIT reimplementation after ~2 weeks of live use + data collection. Tracked in `FUTURE_WORK.md`.

**Integration points:** Talks to BufferManager (which decides which buffers exist), Tool Registry (ReadNV/WriteNV/EditNV/QueryAST), and Arconaut Logic (which assembles file context into prompts).

**Open questions:**
- Cross-buffer atomic edits: neovim undo is per-buffer. Do we need a transaction coordinator? **Deferred to FUTURE_WORK.md.**
- Can brush shell commands (e.g., `git merge`) trigger neovim buffer updates for conflict resolution?

**Literature support:** CodeStruct (ACL 2026) demonstrates AST-based editing reduces errors **76–88%** and tokens **12–38%**; neovim's built-in tree-sitter enables this without external dependencies.

### 3.2 Brush-Core Shell (ShellRuntime)

**What it is.** A persistent embedded shell via `brush-core` (Rust bash implementation), shared between the TUI terminal panel and the agent. Replaces the `BashTool` in `tools.rs` (lines 267–379) which spawns `/bin/bash` per command with no session state.

**What it replaces.** `BashTool` — single-shot command execution with no TTY, no history, no working directory persistence, and restrictive safety filtering (`is_safe_command`, line 298) that rejects even pipes.

**Key design decisions:**
- **Shared session.** TUI and agent see the same shell state: cwd, env vars, background jobs.
- **Custom builtins.** `arconaut-list`, `arconaut-git-status`, `arconaut-cargo-test`, `arconaut-history` — structured outputs that bypass raw text parsing.
- **OSC 633 terminal integration.** Command text (`E`), Cwd properties (`P`), continuation prompts (`F`/`G`) — a superset of OSC 133 that gives us structured command boundaries.
- **Snapshot sourcing.** Capture `.bashrc` / `.profile` state at startup so the shell behaves like the user's real shell.
- **MSRV bump.** `brush-core` 0.5.0 requires Rust 1.88.0. Bump after P5.7 merge; vendor and pin dependencies.

**Integration points:** Feeds the Structured Shell Log via OSC 633 parsing; receives commands from `RTermWrite`; signals (ctrl-C, ctrl-D) translated by Arconaut Logic.

**Open questions:**
- Brush-core custom builtin registration API is not yet stable.
- `.bashrc` snapshot: do we source at startup or capture env diff?

### 3.3 BufferManager (Predictive Working Set)

**What it is.** A three-level predictive cache that keeps the right files warm in neovim buffers before Megan needs them.

**What it replaces.** The implicit "read file on demand" model where every `ReadTool` call performs cold `tokio::fs::read_to_string` (line 60 in `tools.rs`).

**Key design decisions:**
- **File-level CPT for P5.7.** Block-level CPT is future work.
- **L1: Graph Prefetch.** Parse imports/dependencies; preload 1–2 hops.
- **L2: Markov Transition.** Correlation Prediction Table (CPT) indexed by buffer_id → up to 4 successor buffer_ids, LRU-ordered. 1st-order Markov captures **94%** of predictable file-access structure (Griffioen & Appleton 1994; Joseph & Grunwald 1997).
- **L3: Working Set Clock.** ARC-style adaptive replacement (Megiddo & Modha 2003) with ghost lists and a clock hand for O(1) eviction (Carr & Hennessy 1981).
- **Rescue mechanism.** Predicted buffers get timestamp boost in replacement policy, preventing eviction of soon-to-be-needed blocks (Griffioen & Appleton).
- **Exponential fading.** Hit counters age continuously to handle concept drift (Esfahbod 2006).
- **Warm-start persistence.** CPT and ghost lists persist across sessions when possible; fall back to cold start.
- **Accuracy throttling.** 2-bit saturating counters suppress prefetch when predicted accuracy is low.

**Integration points:** Neovim Headless (opens/closes buffers); Arconaut Logic (injects working set summary into Beat); Soul (indirect — Megan benefits from faster reads).

**Literature support:** Griffioen & Appleton (1994) — probability graph + rescue; Joseph & Grunwald (1997) — CPT with LRU successor ranking; Denning (1968) — working set theory; Carr & Hennessy (1981) — WSClock O(1) eviction; Megiddo & Modha (2003) — ARC self-tuning replacement; Jiang & Zhang (2002) — LIRS inter-reference recency.

### 3.4 TUI Terminal Panel (RTerm)

**What it is.** The right-side terminal tile in the ratatui TUI. **CRITICAL: This is the agent's terminal, not the operator's.** The operator CAN type into it, but it exists first and foremost for Megan's persistent shell access — SSH sessions, Docker exec, kubectl, long-running TTY processes.

**What it replaces.** Any notion of a "human convenience terminal." This is first-class agent infrastructure.

**Key design decisions:**
- **Railroad traffic signaling.** Visual state overlay (ratatui): 🟢 idle (human free), 🟡 agent about to send (wrap up), 🔴 agent has control (do not type), ⚡ interrupt sent.
- **Human input is secondary.** The shell session persists across turns regardless of who typed last.
- **No raw TTY in agent context.** Agent never sees escape sequences; only the structured log.
- **All logs retained.** No defined truncation period. Store in sharded, compressed files that don't grow unbounded individually.
- **Remote files visible to agent.** When Megan SSHs into a remote host, she accesses remote files via explicit `remote_*` tools (Phase B), not through terminal scraping.

**Integration points:** Brush-core shell (process + TTY); Structured Shell Log (output destination); Arconaut Logic (railroad signal state machine).

**Open questions:**
- Remote network host tomography (latency, packet loss) — **deferred to FUTURE_WORK.md**.

### 3.5 Structured Shell Log

**What it is.** A hyper-structured neovim-native log format that replaces raw terminal output in Megan's context. Parsed from OSC 633 sequences, stored as a persistent nvim buffer and on-disk file.

**What it replaces.** The current `BashTool` output format: `exit_code: N\nstdout: ...\nstderr: ...` (lines 365–367 in `tools.rs`).

**Key design decisions:**
- **Custom grammar.** A dedicated grammar optimized for Megan's ease of use — not raw markdown, not ad-hoc text. Queryable structure.
- **Cursor remembers position.** Megan's last read position is persisted; `RTermRead` returns only new content.
- **Interception architecture.** Megan writes a command entry → Arconaut extracts → submits to shell → only logs if command actually launches.
- **Shorthand codes.** `^C`, `^D` translated to control signals, not literal text.
- **Dual fidelity.** Full-fidelity log retained in audit partition; context window sees summarized / structured view.

**Integration points:** Brush-core (receives commands, emits OSC 633); Neovim Headless (log is always-open buffer); Soul (reads via `RTermRead`, writes via `RTermWrite`).

### 3.6 Tool Registry (Base Tools)

**What it is.** The complete P5.7 tool inventory. Old tools deleted; new tools are structure-native.

| Tool | Type | Megan Facing? | Replaces |
|------|------|---------------|----------|
| **ReadNV** | Code | ✅ | `ReadTool` (line 14) |
| **WriteNV** | Code | ✅ | `WriteTool` (line 83) |
| **EditNV** | Code | ✅ | `EditTool` (line 160) — string replacement |
| **QueryAST** | Code | ✅ | `GrepTool` (line 385) — text regex |
| **File** | File | ✅ | — |
| **BrushTool** | Shell | ✅ | `BashTool` (line 267) — one-off execution |
| **RTermRead** | Shell | ✅ | `BashTool` output parsing |
| **RTermWrite** | Shell | ✅ | `BashTool` command execution |
| **RemoteRead** | Remote | ✅ | — |
| **RemoteWrite** / **RemotePatch** | Remote | ✅ | — |
| **RemoteSearch** | Remote | ✅ | — |
| **RemoteExecute** | Remote | ✅ | — |
| **VImage** | Vision | ✅ | — |
| **Web** | Web | ✅ | — |
| **Neurotic** | Library | ✅ | — |
| **Beat** | State | ✅ | — |
| **Vectored** | Embeddings | ❌ | — |

**Key design decisions:**
- `EditNV` supports two modes: `query` (tree-sitter selector) and `extmark` (semantic label).
- `QueryAST` returns JSON-structured AST nodes, not raw text.
- **`File` tool** — three verbs:
  - `Glob(pattern)` — returns matching file paths (e.g., `crates/**/*.rs`).
  - `ListDir(path)` — returns directory entries with metadata (name, type, size, modified, git status).
  - `Tree(root, depth)` — returns recursive directory structure, capped at `depth` to prevent runaway output.
- **`BrushTool`** — one-off command execution via `brush-core` without the persistent shell round trip. Returns structured output (exit code, stdout, stderr, duration, cwd). Does not mutate the shared RTerm session state. For quick commands: `cargo test`, `git diff`, `rustc --version`.
- `Neurotic` has two verbs: `Browse` (general query) and `Seek` (deep research request).
- `Beat` auto-injected every turn; `Beat Taken` triggered post-compaction, on session resume, on Tempo change, and on heuristic escalation.
- **Schema versioning:** Sequence numbers per tool. No backward compatibility burden during P5.7 — we bump the sequence number when the schema changes and update callers.

**Integration points:** Tool Registry talks to Soul (which calls tools) and Arconaut Logic (which assembles tool results into context).

### 3.7 Vectored Tool (Trajectory, Assemblage, Rhizome)

**What it is.** A system-level ambient intelligence tool, NOT Megan-facing. Arconaut fires it automatically when heuristics detect struggle. Results are synthesized into concise system messages — Megan never sees raw embedding scores.

| Verb | Corpus | Use Case |
|------|--------|----------|
| **Trajectory** | Embedded audit log | "Have I seen this error before? How did I fix it?" |
| **Assemblage** | Embedded repository | "Where is the relevant code for this feature?" |
| **Rhizome** | Library embeddings (~5,300 papers) | "What does the literature say about this problem?" |

**Key design decisions:**
- **Heuristic-triggered only.** Flailing (>3 same errors), debug struggle (>5 turns no progress), unknown domain, context drift, long pause.
- **Independent triggers.** Trajectory, Assemblage, and Rhizome are not a cascade. The heuristic engine decides which to fire based on the situation.
- **Synthesized injection.** Megan sees: "[Context] You've fixed this unwrap panic before in `auth.rs`." Never raw similarity scores.
- **Silence is free.** If nothing useful, no tokens burned.
- **Deferred to later tranche.** Interface designed in P5.7; implementation blocked on embedding infrastructure and `nl` binary upgrade.

**Integration points:** Soul v2 (heuristic detection feeds trigger signals); Arconaut Logic (constructs query, synthesizes results, injects into context); embedding infrastructure (deferred).

### 3.8 Soul v2 (Turn Orchestrator)

**What it is.** The refactored LLM turn loop. Current implementation in `soul.rs` (lines 14–299) mixes Soul and Arconaut concerns. v2 strips environmental management and adds Tempo governance.

**What changes from current `soul.rs`:**
- **Remove:** Direct compaction invocation (line 130–132) → Arconaut Logic handles this.
- **Remove:** Direct injector invocation (line 134–136) → Arconaut Logic assembles context.
- **Remove:** `BashTool`, `ReadTool`, etc. from registry → only NV, File, BrushTool, RTerm, Remote, VImage, Web, Neurotic, Beat tools.
- **Add:** Tempo state machine — checks Tempo before deciding narration level and batching.
- **Add:** Checkpoint decisions for MainCharacter mode.
- **Keep:** Turn execution (line 127), tool calling (line 190–200), dedup (line 128, 282–284), max_steps (line 141), churn detection (line 152–176), assistant off-pulse (line 228–250).

**Key design decisions:**
- **Composable turn phases.** Each turn: `Arconaut.assemble_context()` → `Soul.execute()` → `Arconaut.process_results()`. The Soul operates on Arconaut's best-effort assembly and can request additional context/files as needed.
- **Tempo-aware batching.** In Tuned mode, the Soul may issue parallel tool calls where dependencies allow; in Metronome, sequential only.
- **Deduplication persists.** `Deduplicator` (line 20, 128) still prevents identical tool calls within a turn.
- **Tempo set by operator.** Soul can request changes; Arconaut can suggest changes (e.g., long spec paste → suggest MainCharacter); operator has final say.
- **Cascading conditional checkpoints.** TBD exact heuristic set. Soul v2 supports checkpointing; Arconaut Logic decides when to fire them based on Tempo and heuristics.

**Integration points:** Arconaut Logic (receives assembled prompt, returns tool results); Tool Registry (calls tools); Assistant Model (off-pulse intervention, reflection, compaction).

### 3.9 Arconaut Logic Layer

**What it is.** A new architectural layer — not present in current code — that owns everything the current Soul does that isn't reasoning: context assembly, heuristic detection, ambient intelligence, operator interface, runtime orchestration. Lives in the `arconaut_reactor` crate.

**Key design decisions:**
- **Context Assembly.** Builds the prompt from: history + Beat (auto-injected) + working set summary + Vectored results (if triggered) + user input. Uses position-aware placement: Beat at end ("lost in the middle" protection per Liu et al. TACL 2024), working set after user input.
- **Heuristic Engine — Tier 1 (rule-based, now).**
  - **Doom-Loop Detector:** Same `(tool, args)` fingerprint ≥3× in 20 turns → warning; 4× → `Intervention::Pause`.
  - **Premature Patching Detector:** Edit before ≥2 reads/search in first 10 turns → nudge.
  - **Test-Fix Loop Detector:** `edit → test_fail → edit` ≥3× with no new reads/search → flag fixation.
  - **Token Burn Alert:** >2σ above session mean, or cumulative >80% context window → pre-compaction warning.
  - **Idle / Stalled Detector:** 3 turns text-only, or 10 min wall-clock since last successful tool execution → prompt to act or complete.
  - **Wrong-File Bounce:** Edit, revert, re-edit same file within 5 turns without touching related files → flag architectural gap.
  - **Validation Avoidance:** Declares done without running tests/linter after edits → block submission.
  - **Syntax Error Cascade:** ≥2 syntax/compilation errors in consecutive edits → halt edits, force read-only review.
- **Heuristic Engine — Tier 2/3 (state-machine / ML, later).**
  - Progress Velocity Score; Trajectory Markov Monitor; Context Pressure Predictor.
  - Behavioral Signature Classifier on audit logs; ProMAS-style Markov velocity; LLM-judge root-cause layer checker.
- **Ambient Intelligence.** Auto-fires `Neurotic Browse` on unknown domains; auto-injects working set changes; manages railroad signals.
- **Off-pulse support.** Assistant model triggered by Arconaut heuristics, not Soul events. Also serves as the reflection model for AgentDiet-style compaction.
- **Principle:** Epistemology is a core action discipline. Arconaut Logic actively tracks what Megan knows, what she should know, and what she's ignoring.

**Integration points:** Everything. This is the central nervous system.

---

### 3.10 Audit & Logging

**What it is.** Full-fidelity record of every turn, tool call, output, and state change. Structured, partitionable, and the corpus for `Trajectory` embeddings.

**Key design decisions:**
- **Dual emission.** Every output produces: (a) original full-fidelity for audit, (b) minimized version for agent context. Original never enters token budget.
- **Partitioned storage.** Turn-level logs, shell log (structured), neovim undo history, extmark state, BufferManager CPT snapshots.
- **Embedding target.** Audit log is the corpus for `Trajectory` — past errors, resolutions, patterns.
- **Retention.** Embed ALL sessions. TTL configurable, default 14–21 days.
- **Minimizer.** Deferred to a later phase; full-fidelity audit is non-negotiable.

**Integration points:** All subsystems emit to audit. Vectored Tool reads from audit embeddings.

## 4. Data Flows

### 4.1 Standard Turn (Metronome Tempo)

```
Operator input → Arconaut Logic
                    ├── assembles context: history + Beat + user input
                    └── compacts if over budget
                        ↓
                  Soul.run_turn()
                    ├── build_request() → ChatRequest
                    ├── provider.chat(request) → ChatResponse
                    ├── extract_tool_calls()
                    ├── execute_tool_call() → ToolResult
                    │     └── (ReadNV, RTermRead, etc.)
                    └── loop until no tool calls
                        ↓
                  Arconaut Logic
                    ├── post-turn hooks
                    └── append to audit log
                        ↓
                  Narration → Operator
```

**Note:** The Soul sees Arconaut Logic's best-effort assembly and can request additional context or files as needed.

### 4.2 Deep Implementation Session (Tuned Tempo)

```
Operator: "Implement OAuth flow"
                    ↓
Arconaut Logic: detect spec-length → suggest Tuned::Implementation
                    ↓
Soul enters Tuned mode (minimal narration, parallel batching)
                    ↓
Turn 1: QueryAST("OAuthFlow") → ReadNV(auth.rs) → ReadNV(oauth.rs)
        [parallel where independent]
        → brief summary only
Turn 2: EditNV(auth.rs, query="fn refresh_token") → EditNV(oauth.rs)
        → brief summary only
Turn 3: RTermWrite("cargo test") → RTermRead (structured log)
        → brief summary: "109 passed, 0 failed"
        ↓
Arconaut Logic: detect all green → allow Soul to continue or pause
```

**Note:** Exit from Tuned mode is operator-only for now.

### 4.3 Heuristic Trigger Firing Vectored Tool

```
Soul executes EditNV → error: "unwrap panic in token.rs"
        ↓
Turn 2: EditNV → same error
Turn 3: EditNV → same error
        ↓
Arconaut Heuristic Engine: flailing detected (same error >3×)
        ↓
Construct contextual query:
  "unwrap panic in token.rs"
  + current goal: "Implement OAuth flow"
  + recent errors
        ↓
Fire Vectored::Trajectory (audit log embeddings)
  → Hit: "Fixed similar unwrap in session X by replacing with ?"
        ↓
Synthesize into system message:
  "[Context] You've fixed this unwrap panic before in `auth.rs`. 
   The fix was replacing unwrap with the ? operator."
        ↓
Inject into Soul context (next turn prompt)
        ↓
Soul continues with injected insight
```

**Note:** Trajectory, Assemblage, and Rhizome are independent triggers selected by the Heuristic Engine, not a fixed cascade.

### 4.4 Compaction + Beat Taken Recovery

```
Context exceeds 180K / 200K tokens
        ↓
CompactionEngine fires (currently line 130–132 in soul.rs,
moves to Arconaut Logic in v2)
  - Summarize oldest turns using cheaper model
  - Archive full fidelity to audit partition
  - Reduce context to ~100K tokens
        ↓
Arconaut Logic auto-injects Beat Taken:
  ```
  base_dir: /Users/patrickbeam/projects/arconaut
  work_dir: crates/arconaut-agent
  session_elapsed: 2h 17m
  active_phase: "Implement OAuth flow"
  last_tool: EditNV
  last_file: token.rs
  compactions: 4
  context_used: 100K / 200K
  working_set: [token.rs, oauth.rs, auth.rs]
  last_test_run: 109 passed, 0 failed
  ```
        ↓
Soul receives compacted history + Beat Taken
  → "Where was I? Right, fixing the unwrap in token.rs..."
```

**Note:** Beat Taken is also auto-injected on session resume, Tempo change, and heuristic escalation (e.g., Doom-Loop pause).

## 5. Token Budget Architecture

### 5.1 Flow

```
Total Budget: 200K tokens target, clamped to model context minus headroom
├── System prompt: ~2K (fixed)
├── Tool schemas: ~8K (fixed, all base tools)
├── Beat (auto-injected): ~500 tokens/turn
├── Working set summary: ~2K tokens (adaptive)
├── Vectored results (if triggered): ~1K tokens
├── User input: variable
├── History (compacted): remainder
└── Headroom: 10K minimum
```

The budget is **hybrid**: 200K is the target, but Arconaut clamps to `min(200K, model_context_window - headroom)` per provider capability map.

### 5.2 Compression Strategies

| Strategy | Technique | Phase | Expected Savings | Applied To |
|----------|-----------|-------|------------------|------------|
| **Trajectory reduction** | AgentDiet reflection | D (default off) | 39.9–59.7% input tokens | Turn history compaction |
| **Prompt compression** | LLMLingua-2 (BERT classifier) | D (default off) | up to 20× | Audit log summaries, old history |
| **Code-specific** | LongCodeZip | D (default off) | up to 5.6× | File reads, AST query results |
| **Tool output minimization** | Anthropic token-efficient tool use | C/D | 14–70% | Shell logs, test outputs |
| **Position-aware** | LongLLMLingua reordering | C/D | 94% cost reduction | Working set injection |
| **Lost-in-middle protection** | Document reordering | C/D | quality recovery | Working set placement at context edges |
| **Speculative decoding** | EAGLE-2/3 | D (default off) | 3–5× generation speedup | Decoding layer; validation in Phase 7 |

**Notes:**
- AgentDiet and LLMLingua-2 are both implemented as toggles in the Efficiency menu, default off. Ablate in Phase 7.
- EAGLE-2/3 is implemented as a toggle, default off. Its interaction with structured tool generation is unproven; measure grammar-violation rate in Phase 7.
- Prefix caching is intentionally skipped for now — it only applies to self-hosted inference stacks.

### 5.3 Cost Modeling per Tempo

| Tempo | Avg Tokens/Turn | Avg Turns/Task | Total Tokens | Notes |
|-------|-----------------|----------------|--------------|-------|
| **Metronome** | ~5K | 20 | ~100K | High narration overhead |
| **Tuned::Impl** | ~15K | 10 | ~150K | Batch parallelism, minimal chat |
| **MainCharacter** | ~50K | 5 checkpoints | ~250K | Long-horizon, compacted mid-flight |

## 6. Implementation Sequencing

### Phase A: Foundation (Parallelizable)
1. **Crate split:** Create `arconaut_pilot` (Soul) and `arconaut_reactor` (Logic). Move relevant code; keep tests green.
2. **Neovim RPC wrapper:** `rmp-rpc` + `arconaut.lua` + prototype `nvim --embed` hello world.
3. **Brush-core integration:** Hello world with custom builtin stub, OSC 633 parsing.

### Phase B: Core Tools (Blocked on Phase A)
4. **ReadNV / WriteNV / EditNV / QueryAST** — neovim-native replacements.
5. **Structured Shell Log** — OSC 633 parser + log format.
6. **RTermRead / RTermWrite** — shell tool replacements.
7. **Remote tools** — `remote_read_file`, `remote_write_file` / `remote_patch`, `remote_search`, `remote_execute` over SSH with `ControlMaster`.

### Phase C: Intelligence (Blocked on Phase B)
8. **BufferManager** — CPT + ARC + prefetcher.
9. **Beat** — pilot variable schema + auto-injection.
10. **Heuristic Engine** — Tier 1: Doom-Loop, Premature Patch, Token Burn, Max Turns.

### Phase D: Advanced (Blocked on Phase C)
11. **Vectored Tool** — interface only; full implementation blocked on embedding infrastructure.
12. **Neurotic Tool** — blocked on `nl` binary upgrade.
13. **Tempo: MainCharacter / Evolving** — checkpoint logic.
14. **Efficiency toggles** — AgentDiet, LLMLingua-2, EAGLE-2/3 speculative decoding. All **default off**.
15. **Tier 2/3 heuristics** — Progress Velocity, Trajectory Markov Monitor, learned classifier.

### Beyond P5.7
