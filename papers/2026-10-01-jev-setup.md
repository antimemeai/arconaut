Jev supplies typed judgments, not generated code or discussion. It can challenge
a proposed oracle or indicate a source contradiction; a reasoning colleague owns
the investigation and actual tests. It is never a correctness oracle or approval
gate. Hashing, exact matching, arithmetic and effect execution remain owned code.

## Implemented development utility

[Written setup sub-plan and usage](../tooling/JEV.md),
[owned wrapper](../scripts/jev-check.py), and
[bounded foundation case](../tooling/jev-cases/review-foundation.json).
This development-only Python utility invokes the existing owned client; Python
does not enter production. It snapshots named complete Markdown sections and
whole-file/section hashes with exact questions and a pinned model. Offline
preparation is the default. Explicit live use creates a distinct ignored run
directory and records the actual model, raw probabilities and usage. It neither
reads credentials itself nor silently caches/reuses judgments.

Source reads and total serialized request are bounded by 65,536 bytes; that is a
local byte limit, not an exact token estimate. Source paths must resolve inside
the repository and cannot name credential files. Caller-selected case contents
are explicit and must be inspected before a new live case. Shared client calls
have a 120-second total process limit; the client independently has bounded
HTTP overload/rate-limit retries and rejects authenticated redirects.
