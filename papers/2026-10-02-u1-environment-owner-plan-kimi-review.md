# Independent review: "Environment owner implementation refinement" (docs/U1_CONTINUATION_SUBPLAN.md:40–192)

Scope inspected: the full new section (lines 40–192), plus targeted existing machinery — `include/arconaut/retained_state.hpp` (Snapshot, private apply/existing/append/attempt/source declarations), `src/retained_state.cpp` (key/apply/rebuild/append_impl/retain_rejection/source/confirm_recovery/reconcile/reserve_identity), `include/arconaut/environment_head.hpp`, `src/environment_head.cpp` (create/open/replace), and `JournalHeader`/`JournalCapacity` operands in `include/arconaut/journal.hpp`/`journal_writer.hpp`. No other subplan sections or tests were read; this is a plan-level review, so findings are about contradictions/missing operands the implementation would hit, not code defects.

Most of the section is internally consistent with the existing machinery: member-order ownership (head before semantic owner) gives correct destruction order; `EnvironmentHead::replace`'s attempted/published transaction (src/environment_head.cpp:83–93, 291–311) matches the "healthy known-head failure permits retry, uncertain publication requires reopen" rule; the facade is workable because `FramedJournal::create` takes `JournalDirectory&` (non-consuming); replay-before-ordinary-batches matches `apply()`'s refusal of maintenance events (src/retained_state.cpp:169–172); entropy sampling (≤32 candidate IDs each checked against every selected header) is count-independent of max_segments and coherent.

## Finding 1 (correctness contradiction): creation holds no lease while creating the root

Plan lines 95–101: "Factor private EnvironmentHead allocation from its existing initial storage publication. RetainedEnvironment first owns the allocated, unhealthy head/directory **without I/O**, then creates/synchronizes its root through the borrowing facade, then calls the head's initial publication." The permanent lease is only acquired inside what is being factored as "publication": `create_exclusive("authority")` + `lock_writer()` (src/environment_head.cpp:195–201).

- Trigger: two creators race the same directory (operator retry after a crashed create, or any caller of the still-public `EnvironmentHead::create`, which "keeps its current behavior by composing those phases"). Both privately allocate "without I/O"; both create root journals (different root headers → different `journal.<hex>` names, so `create_exclusive` does not serialize them); the first to reach publication wins the authority lease.
- Consequence: the environment's root is created outside the "one permanent environment writer lease for its entire lifetime" (lines 19–20, 24). The loser fails only at publication, leaving a competing root file the winner never declared; the winner publishes a head over a directory whose root it did not create or validate. Failure is eventually detectable (open's header comparison), but the lease invariant the section relies on for source routing and continuation does not cover creation.
- Minimal correction: split the factored phases as (a) allocate **and acquire the authority lease** (`create_exclusive("authority")` + `lock_writer()`, writing/syncing the root header, no selector write) and (b) publish the initial selector (`write_selector` + `healthy_`). Root creation/sync happens between (a) and (b) under the held lease; a second creator fails at (a) before touching any journal. Amend "without I/O" to "without selector publication". `EnvironmentHead::open` already fails concretely on a lease-without-selector partial creation (`read_selector` ENOENT, src/environment_head.cpp:137–140), preserving "partial creation files remain evidence."

## Finding 2 (missing state operand): no mechanism/operand keeps captured source chunks out of `ordinary_sources`

Plan lines 119, 131, 134: "captured source chunks remain physical inspection metadata and are not ordinary_sources"; "original proposal sources cannot satisfy ordinary dependencies." Existing `rebuild()` pushes **every** staged `FrameKind::source` record into `candidate.sources` before decoding the batch's semantic records (src/retained_state.cpp:320–327), and `retain_rejection` writes chunk groups in batches physically *before* the marker batch (src/retained_state.cpp:641–655), with the marker's dependency list being the only thing that identifies the chunks as captures.

- Trigger: reopen an environment containing a retained rejected proposal, then submit an event whose `dependencies` reference a captured chunk's `RecordReference`. An implementation that keeps the current per-batch source admission finds the chunk in `snapshot.sources` and admits the dependency (src/retained_state.cpp:173–182), contradicting line 131.
- Consequence: captured/diagnostic bytes become ordinary dependency authority after replay, exactly the provenance confusion the section forbids.
- Minimal correction: name the operand and ordering explicitly — replay must classify a source record as capture-only at marker validation (marker reference set staged in the Snapshot), defer or retroactively exclude those records from `ordinary_sources` (safe because chunks/marker are contiguous with no interleaved admitted events), and have dependency admission consult only the ordinary set. As written, "Their source chunks never become ordinary sources" covers choice/capture maintenance but the rejected-proposal diagnostic path and its cross-batch chunk/marker ordering are unspecified.

## Finding 3 (missing state operand): per-namespace issuer reset/burn has no storage

Plan lines 138–140: "Reset the active issuer counter when entering a new unique namespace… Burn a decoded uncommitted pending reservation only for its own active namespace." Current `Snapshot` carries a single `counter` (include/arconaut/retained_state.hpp:105), `apply()` conflicts any reservation with `counter <= snapshot.counter` (src/retained_state.cpp:191–194), and `pending_counter_` is a single namespace-blind max (src/retained_state.cpp:378). The namespace-qualified reservation *key* is correctly demanded by the plan (current `key()` zeroes the namespace bytes, src/retained_state.cpp:30–37 — a covered extension), but the reset/burn rules additionally require the Snapshot and pending state to record the **active issuer_namespace** (from the active segment header). No such operand is named anywhere in the section; without it "its own active namespace" is unimplementable. Minimal correction: add an explicit active-namespace field to the staged Snapshot/pending accounting and state that namespace transition is detected from each selected header during restage/replay.

## Finding 4 (false refusal semantics): mixed-proposal refusal uses `AuditUnavailable`

Plan lines 70–72: a mixed proposal (exact uncertain identity + new events) is "refused AuditUnavailable before append." Everywhere else in this contract `audit_unavailable` is state-dependent and retry-meaningful (state not live, src/retained_state.cpp:402–404; unhealthy head, src/environment_head.cpp:283–284). A mixed proposal is a permanently invalid input: identical retry never succeeds, yet the code signals a transient condition and invites recovery workflows, and it diverges from the very next sentence's policy that stale uncaptured proposals "retain ordinary rejected-input evidence." Minimal correction: refuse with `conflict`/`invalid_range` (and state whether evidence is retained, like other rejected input), reserving `AuditUnavailable` for genuine unavailability.

## Minor clarifications (not blocking)

- Line 66: "An exact previously captured proposal returns its original event records with Uncertain evidence." Captured events were never committed, so these records are descriptor-derived predicted sequences (`{journal, first_sequence + source_count + i}`), not acknowledged records. Since `Submission.record` is otherwise authoritative (src/retained_state.cpp:676, 686), state explicitly that Uncertain-evidence records are predicted provenance.
- Line 165: "Raw-range inspection remains available under the lease" during live restage should be qualified — either it serializes on the journal descriptor lock or returns `Busy` like payload validation under the physical-replay contract — so the two contracts cannot be read as contradictory for the same journal object.
- Line 177: "at most32" typo.

## Verdict

Not ready as-is. Finding 1 contradicts the section's own permanent-lease invariant during creation; Findings 2 and 3 are missing state/ordering operands without which the stated provenance and namespace semantics cannot be implemented as specified; Finding 4 is a wrong refusal class. All four have small, local textual corrections. Everything else I checked (ownership/destruction order, publication/retry semantics vs `EnvironmentHead`, batch-atomic replay vs `apply()` refusal of maintenance events, budget definitions, entropy sampling, continuation publication order) is consistent with the existing targeted machinery.
