## Independent review: selected-chain maintenance wire codecs (kinds 12/13) + root refusal

Scope inspected: supplied excerpts of `docs/U1_CONTINUATION_SUBPLAN.md` (format section), `include/arconaut/retained_events.hpp`, `src/retained_events.cpp`, `tests/retained_events_test.cpp::continuation_wire()`, `src/retained_state.cpp::apply()` gate, `tests/retained_state_test.cpp::root_refuses_continuation_records()`. I did not treat the explicitly pending owner/semantic placement/required-set/source-routing/custody validation as claimed.

### Format conformance checks (verified correct)

- **108+20A+36C body**: envelope is 8 bytes (schema u16=1, kind u16, dep count u32); fixed choice body offsets 8–107 (=108 bytes) match the spec layout exactly — predecessor journal16/seq u64/end u64, diagnostic u64, available u64, old payload/batch u32s, old/new file/records u64s, present u16/code u16/detail u64. Checked entries are 20 bytes (attempt16/opened/phase/disposition/evidence), descriptors 36 bytes (origin16/seq/len/purpose/reserved). Test vectors independently confirm offsets (e.g. `choice[57]=4`→1024, `full[216]=255,[217]=1`→511).
- **Count-before-allocation**: checked count is bounded by `(remaining-4)/20` before `reserve` (src/retained_events.cpp, case 12, the guarded `if` with `decoder.remaining() < 4`), capture count by `remaining/36`, envelope dep count by `remaining/24`, identity vectors by `remaining/16`. All reserves occur only after bounding — matches "bounded by actual body length before allocation".
- **Canonical ordering/unique/nonzero**: `valid_choice` enforces strictly ascending attempt-ID bytes (`>=` rejects duplicates and inversions, tested via `bad_choice_byte(147,7)`/`(147,6)`), descriptors strictly ascending via `capture_less` (origin bytes, then sequence, then purpose — tested by `(207,11)` and the duplicated-descriptor case). Zero attempt/origin rejected via `Id::from_bytes` (tested `(127,0)`, `(171,0)`); nonzero `first_sequence` and `proposal_length >= 48` in `valid_capture` (tested `(172,0)`, `(180,47)`).
- **Boolean/phase/evidence/error fields**: `opened ≤ 1` (`(128,2)`), `phase ≤ 3` with 0=none (`(129,4)`), `disposition ≤ 4`, phase/disposition coherence via `valid_observation` including the exhaustive 5×6 sweep, `evidence ≤ 3` (`(131,4)`), `present ∈ {0,1}` (`(96,2)`), absent problem requires zero code/detail (`(96,0)`), code ≤ `audit_unavailable` (`(98,255)`), purpose full-u16 range 1–2 (`(188,0/3)`, `(189,1)`), reserved u16=0 (`(190,1)`). Encode-side `valid_body` mirrors all of these (tested by swapped checked attempts / reversed captures / dependency-rule violations failing encode).
- **Envelope rules**: kind 12 with dependencies and kind 13 without dependencies rejected both on encode (`invalid_range`) and decode (`corrupt`) — both directions tested (`dependency_choice`, `dependency_wire`, `missing_chunk`, `missing_chunk_wire`).
- **Truncation/capacity/trailing**: full 0..n-1 truncation sweep on all three vectors asserts `corrupt`; max_payload-1 asserts `capacity` on both decode and encode; trailing byte rejected. Allocator-cut sweep resets `fail_allocation` before inspecting results and asserts only `allocation` errors surface, for both encode and decode paths.
- **Root refusal**: `apply()` (src/retained_state.cpp ~line 167) rejects both kinds with `unsupported` before any other handling, so it is evidence-independent — covers live and replay. Live path tested (append → `unsupported`, `RejectedSubmissionEvent` recorded, still `live`); replay path tested (physical commit of a semantic maintenance record → recovery problem `unsupported`, blocked, zero committed facts, cursor unchanged at end_offset 112, storage bytes unchanged, dispatch refused with `audit_unavailable` and no effect call).

### Production bugs found

None in the scoped code. The codec checks are exactly the format checks; environmental rules the spec assigns to the owner (predecessor==header predecessor, range inequalities, old limits == predecessor header, new capacities == candidate, sequence-1/exactly-one placement, descriptor↔marker cross-check, reconciliation-set equality, uncertain-index rules) are correctly absent from the codec and correctly gated in `RetainedState`. I found no invented format restriction either (e.g. predecessor sequence 0 is accepted, matching the spec's silence; `detail` i64 congruent conversion is specified).

### Oracle weaknesses (minor, test-side)

1. **Trailing-material rejection lacks an error-code assertion** (tests/retained_events_test.cpp, the `trailing.push_back` check): only `!has_value()` is checked, unlike truncation which pins `corrupt`. A regression returning `capacity`/`unsupported` for trailing bytes would pass. Red: assert `.error().code == ErrorCode::corrupt`.
2. **Decode allocator sweep discards the decoded value**: on the first succeeding cut the decode branch returns an empty vector without verifying the decoded event equals the expected structure or re-encodes to `full`. Red: on success, `CHECK(parsed.value() == populated)` (or round-trip equality) before breaking.
3. **Root replay exercises one placement only** (semantic record after one source frame). The `apply()` gate is kind-based so this is not a coverage hole for the claimed boundary, but there is no test that kind 12/13 in a *later batch of a non-root segment* is rejected — correctly so, since that placement rule is pending owner work; just don't read this test as covering placement.
4. No explicit assertion that an unknown kind (e.g. 14) yields `unsupported` while malformed 12/13 yields `corrupt`; the `default` case exists but is untested in this excerpt (may be covered by earlier kind 1–11 tests outside the supplied scope).

### Verdict

**Approved within scope.** Kinds 12/13 implement the exact specified codecs with correct bounds-before-allocation, canonical ordering, field validation, envelope rules, and exhaustive truncation/capacity/allocator evidence; kinds 1–11 are untouched; root refuses maintenance both live and replay. The only unresolved items are the deliberately deferred environmental semantics (whole selected-chain owner: placement, required-set cross-check, custody/source routing), which remain open owner work — plus the four minor test-oracle tightenings above.
