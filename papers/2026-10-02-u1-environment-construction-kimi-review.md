# Independent review — U1 first construction stage: RetainedEnvironment + shared RetainedState

Scope read: BLACKBIRD.md, docs/U1_CONTINUATION_SUBPLAN.md, include/arconaut/{retained_environment,retained_state,environment_head,journal_writer}.hpp, src/{retained_environment,retained_state,journal}.cpp, relevant parts of src/journal_writer.cpp, tests/retained_environment_test.cpp. Read-only; no execution (Linux access noted as reset; no host evidence claimed either way).

## Verified defects in supported construction paths

### 1. Deduped "existing" events are still physically appended; dedup result cursor changes
`src/retained_environment.cpp:319-338` correctly pre-stages `result.events[i].existing = true` for events already in `committed_`, but then calls `semantic_->append(expected, sources, events)` with the *full* event list. In `src/retained_state.cpp:527-542`, `apply()` returns success for an exact existing event (`:206-208`) yet `drafts.push_back` still runs, so a duplicate semantic frame is physically written, the commit advances the cursor, and `result.cursor = written.value()` (`:338`) reports a changed cursor.
- **Trigger:** create root env; `submit_proposal` a decision; `submit_proposal` the identical proposal again.
- **Consequence:** result claims `existing` (a no-write dedup result) while a duplicate frame is written, sequence/file/record budget is burned, and the cursor advances — directly contradicting the reviewed subplan: "The current cursor in a dedup result is unchanged … Only a genuinely new append is checked/encoded under the new active header/profile" (subplan lines 99-101). Repeated exact resubmission spuriously exhausts capacity. The physical-duplicate-frame retention rule (subplan 105-108) covers *within-proposal* duplicates only, not cross-proposal committed duplicates.
- **Latent compounding:** once continuation permits a narrowed active payload profile, re-encoding the already-committed event under the new profile (`retained_state.cpp:478-480`) fails *before* any lookup — the exact scenario the subplan forbids for dedup.
- **Fix:** filter committed-existing events out of the append (short-circuit all-existing proposals to return the staged result with unchanged cursor); keep physical-frame retention only for within-proposal duplicates.

### 2. RecoveryChoice range checks incomplete — inconsistent choice admitted
`src/retained_environment.cpp:257-261` checks `available_end > predecessor observed extent` and `diagnostic_offset < journal_header_size`, but never checks `choice->predecessor.validated_end_offset <= choice->available_end` nor `choice->diagnostic_offset <= choice->available_end`, both explicit reviewed rules (subplan lines 639-640: "range must obey predecessor.end <= available_end and diagnostic_offset <= available_end"; line 738).
- **Trigger:** hand-built child whose choice declares `available_end = 200`, `diagnostic_offset = 112` while its header predecessor commits end 494 and the file extent is 494. All current checks pass.
- **Consequence:** a chain activates whose choice asserts the predecessor's available end is *smaller* than its acknowledged committed prefix — silent contradiction of declared authoritative history in an apparently supported chain.
- **Fix:** add both comparisons; refuse `conflict`.

### 3. Historical-prefix semantic rejection detected only indirectly via cursor mutation
When `replay()` semantically rejects a batch inside a historical segment, `reject_recovery_batch` shrinks that journal's cursor; the chain is refused only because `retained_environment.cpp:282-284` compares cursor before/after replay and sees a change. This currently works, but nothing directly asserts the reviewed rule "a selected historical boundary that cannot be semantically reached refuses the chain" (subplan 227-228): no check of `journal->recovery_report().clean()` or that the post-replay committed boundary still equals the child's declared selected prefix. Any future change in which rejection preserves cursor (or a batch rejection that happens to land on the same cursor) silently admits shortened history. Recommend an explicit clean-report + boundary-equality check per historical segment after replay. No test currently exercises this path at all (see below), so the indirect mechanism is unverified.

### 4. Corruption latch co-opts `continuation_required_` with an over-broad error taxonomy
`src/retained_environment.cpp:361-366` latches `continuation_required_` on *any* source-read error except allocation/stale_handle/audit_unavailable/busy. That includes transient native read failures (e.g. interruption-budget exhaustion → `incomplete`, or a native I/O error), not just CRC corruption. Per the subplan this latch is the continuation gate, cleared only by successful candidate/head publication — which is unimplemented — so one transient read error permanently bricks ordinary work until reopen, and once continuation lands it would force an unneeded continuation. Meanwhile `state()` reports `blocked` while every underlying journal reports `live` (hpp `:53-62`), misattributing health. Corruption health propagation is required; consider a distinct latch or narrowing the triggering codes to actual integrity failures.

## Intentionally unimplemented (required later, not defects)
Verified the staged refusals are fail-closed: nonempty `required_captures`/`checked_attempts` refuse `unsupported` before any choice fact or replay (`retained_environment.cpp:265-269`); `ProvisionalCaptureEvent`/`RecoveryChoiceEvent` are refused by `apply()` (`retained_state.cpp:202-205`), so capture markers in a segment without declared captures close/reject rather than activate. Live continuation/restage, entropy, provisional/uncertain indexes, `ProposalSubmission.capture` (always nullopt), the raw bad-header inspection helper, and emergency controls are absent as stated. Destruction order is correct (semantic/facade/descriptors before head/directory, hpp `:76-77`), authority precedes root creation and publication follows root sync (`:130-146`), nonzero namespaces are enforced by `decode_journal_header`→`validate_header` (src/journal.cpp:36-39,151), and chain cycle/count/environment/namespace/generation checks are present and sound.

## Missing direct oracles (would expose the above and related errors)

1. **Finding 1:** exact resubmission via `submit_proposal` asserting `existing == true`, cursor unchanged, and physical record count unchanged. No current test covers proposal-level dedup (test line 122 uses single-event `submit`).
2. **Finding 2:** a child choice with `available_end` < predecessor committed end, and one with `diagnostic_offset > available_end`, both refused `conflict`.
3. **Unsupported histories:** no test builds a child with nonempty `required_captures` or `checked_attempts` and asserts `unsupported`. Deleting the guard at `retained_environment.cpp:268-269` fails no test — the refusal that keeps unsupported histories from silent admission is unprotected.
4. **Finding 3 path:** semantically invalid batch (CRC-valid, e.g. invocation referencing a nonexistent decision) inside a *historical* selected prefix must refuse the chain; same invalidity in the active tail must retain a diagnostic prefix with work closed. Untested.
5. **Three-segment oracle (subplan 269-296) only partially implemented:** missing (a) explicit assertion that the two counter1 reservations in different namespaces are both retained facts with *different full IDs* (only the aggregate count 7 is checked, test `:218`); (b) the sufficient-budget branch where a fresh `AttemptOpen` dispatches exactly once and retains its separate adapter receipt (only the budget-10 refusal is tested); (c) any byte-level independent fixture — `history_fixture` builds files through the implementation's own encoders/appends, so a systematic encoder/framing bug would be self-confirming; the literal cursor tuples are good but payload/frame bytes are never pinned to hand-derived vectors.
6. **Chain negatives absent:** cycle, missing selected header file, on-disk root carrying a predecessor, supplied-root header mismatch (e.g. wrong limits — only wrong root *capacity* and wrong choice old-capacity/namespace are tested, `:245-263`), mismatched choice `old_limits`, and a valid later historical suffix that must remain unpublished yet inspectable via `read_original_range`.
7. **Per-descriptor source routing:** the three-source read (`:219-222`) plus one corruption case partially covers this, but there is no negative asserting a source reference naming the wrong journal/sequence is refused `stale_handle` rather than read through the active file.

Root regression/crash suites: root behavior is exercised via `root_owner`/`duplicate_positions` here and the retained root suite remains in place per the subplan; I did not re-audit `tests/retained_state_test.cpp` or `environment_head_test.cpp` beyond confirming the head-phase oracles exist.

Limitations: static review only; no execution on any host; `src/journal_writer.cpp` and `src/environment_head.cpp` were sampled only where environment correctness depended on their contracts.
