**Files inspected:** `src/audit.cpp` (full), `AuditLog` declaration in `include/arconaut/context.hpp`, `audit_inspect`/`rageshake`/`read_process_output` cases in `src/coding.cpp` (lines 748–858), schemas in `src/tools.cpp` (lines 243–263, plus `exec` timeout path 180–241), `tests/audit_test.cpp`, and the `retained_output_test` portion of `tests/coding_test.cpp` (lines 206–339). Root APIs `RetainedState::source` / `committed_facts` were consulted in `include/arconaut/retained_state.hpp` and `src/retained_state.cpp:898` only to verify borrow/copy semantics; `AuditLog::original`/`record` in `src/context.cpp:48–76` were consulted to verify where original bytes live (raw bytes go to journal sources; the event payload is always the `{label, metadata}` JSON packet). No B1 review performed.

## Verified correct (against the listed fault classes)

- **Original bytes not lost/misattributed:** `AuditLog::original` (context.cpp:59–76) stores raw bytes as a journal source with an explicit `SourceReference` dependency computed from the cursor; `audit.cpp:146–152` retrieves exactly that dependency via `root_.source()`, and `tests/audit_test.cpp:50–77` round-trips binary bytes (`A\0\xffZ` → `4100ff5a`) including after close/reopen. The summary `parse_json` at audit.cpp:54 is safe because the event payload is always the JSON packet, never the raw bytes.
- **Bounded results / cursor stability:** `committed_facts()` is snapshotted per call, `end` pins the append-only prefix (audit.cpp:133–136, 171–181), indices are stable within the lineage, `count ≤ 64`, `limit ≤ 65536` enforced (line 136), sources truncated to first 64 with `source_count` total (lines 37–42). Reopen stability is tested.
- **No borrow invalidation:** `inspect` holds the `committed_facts()` span only across `root_.source()` calls, which (retained_state.cpp:898–913) only read journal segments and never mutate `committed_.facts`; same for the `read_process_output` loop (coding.cpp:763–787).
- **Unknown not misreported:** `AttemptObservationEvent` maps disposition through an explicit table including `"unknown"` (audit.cpp:93–95); admission rows say `"not established by admission"` (line 89); `exec` timeout rethrows after capturing `process.partial` (tools.cpp:222–225) so no success exit code is fabricated; `rageshake` sets `bead_created=true` only on literal `exit_code=="0"` (coding.cpp:843–844). coding_test.cpp:276–296 oracles this.
- **Complaint retained before delivery / bead hygiene:** `log_.original({"complaint.detail", ...})` (coding.cpp:823–825) commits before the `bd create` exec (line 828); on bd-missing/error/timeout the complaint is already local and `bead_created=false` (tested via PATH clobber, coding_test.cpp:297–309). The bead carries only the constant title + complaint hex id + conversation hex id — no observation or provider/context content (lines 833–839).

## Findings (minor / documentation-level only)

1. **Undocumented full-source copy for a bounded page** — `src/audit.cpp:150–151`: serving one `limit ≤ 65536` hex page of a source first materializes the *entire* source payload (`root_.source(...)` returns `std::vector<std::byte>`). Per the design constraint this single copy is permitted only if documented; the `audit_inspect` schema (`src/tools.cpp:250`) does not state that a source page read copies the whole payload into memory. Trigger: `audit_inspect` with `record`+`source` on a record whose dependency is a multi-GB provider/context blob. Consequence: transient memory spike proportional to full source size, invisible to the caller. Fix: document the copy in the schema description, or add a bounded `read_original_range`-style source slice (the journal already exposes `read_original_range`, retained_state.hpp:73–76).
2. **`limit`/`count` validated on queries where they are meaningless** — audit.cpp:136 applies `count`/`limit` range checks before the `record`-branch, so `audit_inspect` with `{record:0, count:65}` throws `invalid_range` even though `count` is unused for record reads. Cosmetic; no data consequence. Fix: validate `count` only in list mode, `limit` only in record mode.
3. **`rageshake` `references` object is unbounded** — coding.cpp:805–811 caps `observation` at 65536 but embeds `references` verbatim into the locally retained detail. Local-only, so no leak, but a pathological references blob inflates the audit journal. Fix: cap serialized references size similarly.

## Oracle gaps in the scoped tests

- `tests/audit_test.cpp` never tests: list-mode pagination continuing with a pinned `end` *after* an append (only a single post-append `end` check, line 56–59); a record-mode read *without* `source` (event-payload hex path, audit.cpp:144–145); `count` > 64 rejection; source index out of range (audit.cpp:148); or an `unknown`-disposition row (that is only covered in coding_test).
- `retained_output_test` exercises rageshake only with `bd` absent. There is no test where `bd` **succeeds**, so nothing oracles that the delivered argv/description actually excludes the observation and provider/context content — a future regression embedding `observation` in the bead would pass all tests. No timeout path test for the bd exec either (only ENOENT-via-PATH).
- No test that `audit_end` in the complaint detail equals the committed-facts size at capture time (coding.cpp:819–820), i.e. the locator's pinning semantics are unoracled.
- The PATH restore in coding_test.cpp:305 is not exception-safe; an throw from the rageshake `invoke` would leave PATH clobbered for the rest of the test process (test-harness-only issue).

No consequential faults found in the listed fault classes within this scope. Limitations: `RetainedState::append` sequence-numbering contract underlying the `cursor.sequence + 1` source reference (context.cpp:66–69) was not re-verified beyond the passing binary round-trip test; `CodingEngine::operation`'s error-to-`{"error"}` wrapper was inferred from tests rather than read in full.
