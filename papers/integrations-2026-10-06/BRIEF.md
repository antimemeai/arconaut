# Optional integrations, thematic HUD and multiplayer

Operator discussion2026-10-06. Core requirements, not an adopted dependency/spec:

- A normal Arco install does not carry every integration and its dependencies.
  Common integrations (Linear, Slack, Discord, GitHub, Hugging Face, etc.) are
  optional packages/plugins or an equivalent mechanism. Discuss dependency choices
  before adopting; reference source does not select runtime or library.
- HUD means thematic current events relevant to a selected project set: CVEs,
  arXiv topics, financial feeds and other configured sources. It is not the name
  for the harness's runtime status dashboard. Feed observation/triage, human view,
  model context inclusion and station work admission are distinct operations.
- Study current Claude Code teams and mods closely using primary current docs,
  changelog, actual public implementation/examples and tests. Verify version and
  surface differences rather than copy early-access instructions or stale claims.
- True multiplayer is n running Arconauts sharing development/build over network,
  with agent-agent, human-human and human-agent communication. Use n=2 as a concrete
  thought experiment, not fixed topology. Each retains runtime/context/identity;
  communication need not follow spawning trees. Shared source/build identity and
  conflict/reconnect/refit behavior must be explicit. No centralized topology or
  shared-filesystem implementation is selected by this requirement.

Current C++/Lua, model programmability and normal configuration agency, audit and
recoverable original context remain. Default changes activate after affected
turns/workflows conclude; interrupt-and-apply-now remains explicit. Shared kernels,
DBs and fabric services are independently governed; Arco consumes them. Routine
operations do not acquire new approval gates through this study.

Three frumentarii own mods/extension boundary, teams/multiplayer, optional packages/
feeds. Each acquires/reads original docs/source and writes source-located mechanisms,
tradeoffs, limitations and independent behavioral oracles. No product changes,
reference execution, external messages, authentication setup, plugin installation,
UI-framework or service adoption by this research. Existing corpus is reused where
appropriate. Reports under mods/, teams/, feeds/; root integrates results.

Prior slate remains B1 managed compaction -> useful-work evolutionpilot -> giga.
This study informs integrations/HUD discussion and pilot boundaries rather than
silently inserting all multiplayer capabilities as prerequisites.
