### Verified correct (fault-class sweep)

- **Integer overflow / range boundaries** — `range_index` (tools.cpp:89–101) uses `from_chars` with full-consumption and `errc` checks; `"-1"`, `"1.5"`, `"18446744073709551616"` all reject before any effect (test at tools_test.cpp:53–64 confirms no marker file is created). Byte branch (tools.cpp:107–115) rejects `end < start`, clips beyond EOF, omitted end = `max(start, size)` is safe. Line branch (116–134) is 1-based inclusive, retains LF/CR, no phantom line after trailing LF (`"x\n"`, `line_start:2` → `""` covered by test line 112), empty file → zero lines. `SIZE_MAX` default end is safe since loop exit leaves `last = raw.size()`.
- **UTF-8/binary JSON validity** — `display_bytes` (77–88) probes `dump_json(Json{raw})` and falls back to hex; mid-codepoint byte slices and `\0`/`\xff` covered (tools_test.cpp:113–120). Exec budget truncation routes through the same path (tools.cpp:226).
- **Original capture fidelity** — `read_file` captures full raw before presentation slicing (tools.cpp:149–152); exec captures unclipped `process.combined` (tools.cpp:228); observer `process.output` chunks are never clipped. 16 MiB capacity retained (tools.hpp:23–24, tools.cpp:221). Tests assert `captured()[0].bytes == read_file(file)` on every range case.
- **Durable source ordering/attribution** — retrieval (coding.cpp:687–711) iterates `committed_facts()` in order, filters by `metadata.attempt == output_ref`, and concatenates `fact.event.dependencies` via `RetainedState::source` — no cache, side file, or rerun. `provider.calls != 0` is asserted in the test (coding_test.cpp:185).
- **Readback after reopen / timeout partial** — `retained_output_test` closes and reopens via `RetainedState::open` + `confirm_recovery`, retrieves `"cdef"` from a byte-offset slice of an exit-7 attempt, and retrieves `"PARTIAL"` from the interrupted attempt's audit. On interruption, `operation` still logs `operation.result` with `output_ref` and submits an `unknown` observation before rethrowing `interrupted` (coding.cpp:570–602) — exit/error/cancel semantics unchanged.
- **Protocol shape** — without `output_max_bytes` the exec result is legacy `{output, exit_code}`; the two accounting fields are added only when the argument is present (tools.cpp:232–238). `output_ref` is additive. Tool descriptions match implemented semantics (byte half-open vs line inclusive, "never file line semantics" enforced at coding.cpp:715–716).

### Refinements (non-blocking)

1. **Conditional audit-tail gap on timeout** — tools.cpp:222–225: on `collect` throw, `child.take_partial()` goes only to the in-memory `captured_` ("process.partial"), which the A2 contract explicitly excludes as a retrieval source. If `native_process` ever buffers bytes that were read but not yet pushed through `output_observer` before throwing `interrupted`, those bytes are absent from durable `process.output` chunks and `read_process_output` will silently under-report. The current test passes ("PARTIAL" is retrieved), suggesting the observer fires per-read; but there is no invariant or test forcing *every* collected byte through the observer before a throw. Direct red oracle: a child that writes a large burst then exceeds timeout such that the final pipe drain lands in `take_partial()` unobserved — assert durable chunks equal `take_partial()`. Fix if real: route the partial tail through `observer_` in the catch block before rethrow.
2. **Retrieval silently returns empty for known-but-chunkless execs** — coding.cpp:699–703: an `operation.result` for exec sets `known = true` even if zero `process.output` facts exist, so the result is `output:""`, `output_bytes:0`. This matches the A2 doc ("admitted exec with empty output returns empty"), but it also masks a missing-chunk anomaly indistinguishably from genuinely empty output. Refinement only; consider an `attempt`-echo or `chunks` count field to make the two cases distinguishable to an auditor.
3. **Cosmetic** — tool description typo `"timeout_seconds defaults to120"` (tools.cpp:248); test helper `timed_reference` selection (coding_test.cpp:159–168) takes the last `process.output` attempt in the whole log, which would misattribute if the fixture ever grew a third exec — fine today.

**Limitations:** I did not re-read `native_process` (collect/observer emission order — relevant only to refinement 1), `AuditLog`/`RetainedState::source` internals, or `docs/AUTODEV_QUEUE.md`; conclusions on durability rest on the reopen test's behavior and the call sites shown above.
