# Independent persistent and opaque claim review

This bounded independent review challenges selected root-authored claims in OpenClaw, IronClaw and Claude Science. It reads pinned source and official documentation, including relevant assertions; nothing was executed, installed or called with model/provider credentials. Canonical rows were not edited. The shared capability definitions matter: implementation of a scoped hot config swap may earn implementation credit while whole-workflow activation and executable refit remain unproved.

## OpenClaw: continuation custody and channel reload

The row's scoped code-action and owner claims survive source challenge. `createCodeModeRunOwner` captures a runtime-refresh hold, tracks executions, continuation disposal promises and failed cleanup, revokes dispatch on close, waits late executions/disposals, then releases the hold only if no failed cleanup remains. A failed close clears its closing promise for retry while retaining failures/live owner. This is a meaningful custody rule; dropping one tool observer is not enough to erase the cell's owner. [Owner implementation](../../../quarantine/openclaw/src/agents/code-mode-state.ts#L84), [close barrier](../../../quarantine/openclaw/src/agents/code-mode-state.ts#L142).

The narrower interpretation of physical cleanup is essential. The Node pool remains in `retiringPools` while `owner.tasks.close()` is pending or fails; plugin release aggregates cleanup failures. The retained continuation keeps a live pool and explicitly is not a serialized VM image. Every new exec creates a fresh VM context. The row correctly distinguishes a parked cell from a standing general kernel and excludes executable reinhabitation from transcript resume. [Pool owner](../../../quarantine/openclaw/src/agents/code-mode-node.ts#L83), [continuation](../../../quarantine/openclaw/src/agents/code-mode-node.ts#L221), [fresh cell](../../../quarantine/openclaw/src/agents/code-mode-node.worker.ts#L220).

The controlled-promise test attacks dispatch revocation and delayed refresh rather than inferring them from final state. It resolves a late continuation after catalog/abort revocation, withholds cleanup, then asserts disposal and refresh availability only after release. It does not run an independent program or prove every bridged foreign effect stopped. Existing row/test wording appropriately keeps that distinction. [Test oracle](../../../quarantine/openclaw/src/agents/code-mode-state.test.ts#L60).

Channel reload is a separate contract. Its wait returns permission to proceed when active counts drain, but also on lifecycle-lease demand or configured elapsed timeout with counts still positive. The call site uses that result to continue the reload, so this is not merely dead diagnostic text. The canonical limited hot-change/refit cells correctly disclose the escape paths. Do not summarize the cell owner hold as a universal after-turn barrier or zero-active-work refit guarantee. [Active-work wait](../../../quarantine/openclaw/src/gateway/server-reload-active-work.ts#L63), [escape branches](../../../quarantine/openclaw/src/gateway/server-reload-active-work.ts#L85), [actual reload caller](../../../quarantine/openclaw/src/gateway/server-reload-hot.ts#L525).

## IronClaw: executable wiring and provider swaps

The turn/programming limits are supported by current source. DefaultPlanner construction and strategy slots are crate-private and sealed; prompt-mutator patches are not arbitrary strategy replacement. The before-prompt hook port is called by its middleware and is wrapped by the production loop-driver composition with instruction materialization and authority refresh. Thus the prompt hook is actually wired, while the self-authored hook module's types/documentation are insufficient to establish a model-exposed author/register operation. Its own contract limits authorship to restrictions/current run and calls durable authorship future work. A targeted search of turn-runner and first-party host runtime did not find self-authored registration. [Sealed planner](../../../quarantine/ironclaw/crates/loop/ironclaw_agent_loop/src/default_planner.rs#L1), [prompt dispatch](../../../quarantine/ironclaw/crates/loop/ironclaw_hooks/src/middleware/prompt_port.rs#L143), [production wrapping](../../../quarantine/ironclaw/crates/loop/ironclaw_turn_runner/src/loop_driver_host.rs#L1886), [self-authored contract](../../../quarantine/ironclaw/crates/loop/ironclaw_hooks/src/self_authored.rs#L1).

Subagent implementation is not default model availability. Default disabled IDs include spawn_subagent; the actual composition applies that deny list after spawn decoration. The scripted parent/child integration test is ignored with an explicit explanation that it clears this deny list. It has useful parked-parent/child-result assertions for that targeted configuration, without proving default exposure or live unrestricted peer communication. The canonical row gets this distinction right. [Default deny](../../../quarantine/ironclaw/crates/loop/ironclaw_turn_runner/src/runtime.rs#L294), [composition filter](../../../quarantine/ironclaw/crates/loop/ironclaw_turn_runner/src/runtime.rs#L850), [ignored test](../../../quarantine/ironclaw/tests/reborn_subagent_spawn_e2e.rs#L23).

One wording refinement is recommended: **atomic provider swaps are per wrapper, not a single shared generation across primary and cheap**. `SwappableLlmProvider.swap` atomically replaces its provider snapshot under one RwLock; each request clones the current inner Arc and retains it while awaiting. Reload builds a complete candidate before mutations and serializes reload callers, but swaps primary and cheap separately. A concurrent request can observe a new primary while the cheap wrapper still holds the prior generation. No shared pair transaction is traced. This does not invalidate the row's implemented scoped hot-provider change; it bounds any synthesis calling the whole provider pair atomic. Adding a cheap wrapper absent at startup still requires restart. [Per-wrapper snapshot](../../../quarantine/ironclaw/crates/domains/ironclaw_llm/src/runtime.rs#L144), [per-call clone](../../../quarantine/ironclaw/crates/domains/ironclaw_llm/src/runtime.rs#L196), [two swaps](../../../quarantine/ironclaw/crates/domains/ironclaw_llm/src/runtime.rs#L315), [production reload adapter](../../../quarantine/ironclaw/crates/product/ironclaw_operator/src/llm_admin/llm_reload.rs#L86).

The process-lifetime limit is also real: sandbox commands enter a separately spawned owned Tokio task, then the caller awaits the JoinHandle. Dropping the outer await is not a task abort or confirmation of settled container effects. Supervisor cancellation/Drop vocabulary cannot close that inference. The existing limited rebuild/custody statements should remain. [Owned command task](../../../quarantine/ironclaw/crates/lanes/ironclaw_sandbox/src/sandbox_process.rs#L888).

## Claude Science: official contract versus application source

All positive row findings are documented or documentation-bounded limited states; none is promoted to source implementation. Captured artifacts/distributions and an install script do not expose the application engine. Public scientific workflow source elsewhere, including the evidence-database review workflow, is not evidence of Claude Science's internal loop/database. No source tests are reported. These evidence-state choices survive review.

The persistent-kernel limit is explicit: Python/R variables survive steps, but idle expiry, environment restart and session termination end the kernel. Shared named package environments across projects are not a shared persistent kernel service. Local remembered facts do reside in an app database and enter conversations, but this is not a documented generic model SQL/action API or the operator's standing evidence table. [Kernel/environment contract](../../../quarantine/claude-science/raw/tools-and-environments.md#L9), [memory contract](../../../quarantine/claude-science/raw/core-concepts.md#L52).

Artifact provenance is a strong documented research interface: versioned artifacts have messages, reproducible code, execution log, environment and review tabs, with the execution log authoritative when code disagrees. It does not promise retention of all original provider bytes, stdout/stderr, intermediate context transformations or failures outside an artifact lineage. Scratch files explicitly expire. Conversely, the audit limitation must stay **unestablished completeness**, not a factual claim that the opaque engine certainly drops each such category. The existing limited row wording does this. [Artifact retention/provenance](../../../quarantine/claude-science/raw/artifacts.md#L9).

The reviewer checks claims against recorded execution and does not rerun analyses or decide whether the research method was correct. Findings feed the next answer; disabling automatic review leaves pending/active reviews to finish. Delegation runs parallel tracks but Stop ends the whole session and individual tracks cannot be stopped separately. Model switching is documented and remains distinct from addressed live peer collaboration. [Reviewer](../../../quarantine/claude-science/raw/the-reviewer.md#L9), [delegation](../../../quarantine/claude-science/raw/core-concepts.md#L46), [model switching](../../../quarantine/claude-science/raw/safeguards.md#L9).

Configuration TOML is read once at startup. Binary update is signature-verified/atomic replacement with compatibility refusals and restart; neither is self-compiled handoff/reinhabitation with active programs/providers settled and shared services unaffected. Remote Slurm/detached jobs survive connection loss and execute under operator remote authority, a useful consumed-compute contract with no documented universal cancellation/reconnect custody guarantee. The row correctly gives those documented/limited credit. [Startup config](../../../quarantine/claude-science/raw/configuration-file-reference.md#L9), [update](../../../quarantine/claude-science/raw/command-line-settings.md#L14), [remote jobs](../../../quarantine/claude-science/raw/remote-compute-clusters.md#L9).
