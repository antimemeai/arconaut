# Independent renderer review

Reviewed `scripts/render_capabilities.py:1–179` and the six direct-artifact tests in `scripts/test_render_capabilities.py` against `papers/capabilities/README.md` and the registry's identity/group/axis contract. This review checks rendering and validation, not the author's reference capability claims. The scientific/framework studies are not review evidence here.

The renderer correctly checks registered identities and filenames, duplicate axes, the group partition, each row's complete axis set, direct evidence for positive/limited cells, evidence ownership within its own reference, real files and source-line bounds, and inspected/read-only test records. Strict mode rejects missing references; draft matrix/JSON visibly disclose them. Tests compare literal CSV identity/detail and action results, rather than just comparing two transformations of the same object. They also attack cross-reference evidence, impossible source ranges, absent/dangling evidence and missing axes.

Six additional disposable fixtures were constructed by the reviewer's own stdlib script, [renderer-review-probes.py](../../../context/framework-matrix/renderer-review-probes.py), and its assertions were executed once. Exact outcomes are saved in [renderer-review-results.json](../../../context/framework-matrix/renderer-review-results.json). Only the active repository's owned renderer was imported; fixtures lived in temporary directories. No reference product/test was executed, no canonical row or output was rendered/mutated, and no dependency was adopted. The supplied test suite was inspected, not rerun. The findings below are observed acceptance/output failures on those fixtures; they do not assert that the currently authored corpus contains malformed values.

| Finding | Exact mechanism and observed result | Recommended disposition |
| --- | --- | --- |
| R1: malformed typed fields can publish mixed generations | `render_capabilities.py:45–48` checks that `runtime.languages` is a list, but not that its elements are strings. `languages=[17]` passes `load_corpus`. `render:123–124` then overwrites matrix Markdown/JSON; `render:130` raises `TypeError` joining languages. | R2: 23-axis order changes silently rename capabilities | `render:101` zips registry IDs with a separate positional list (`10–13`). | R3: group attribution can disagree between views | `load_corpus:35–36` verifies `groups` partitions IDs but never verifies each `references[].group` against that partition. A reference with `group="other-family"` while listed under `groups.family` passes. Separately, accepted path `quarantine/alpha/source notes.txt` renders a destination containing an unescaped space, which does not form a valid ordinary CommonMark inline link. | Compute the source-relative path from the actual dossier directory. Encode or angle-wrap the destination and escape link text; use the same helper for test-source links. The default `papers/capabilities/dossiers` depth works for simple current paths, so the custom-path finding is bounded to the exposed option. |
| R5: missing rows retain previous dossiers | A complete fixture is rendered, its `beta` row removed, and draft rendering correctly reports `missing=["beta"]`; nevertheless `dossiers/beta.md` remains byte-for-byte from the previous complete render. `render:137–158` creates/replaces current files but never reconciles previous outputs. | Lower-priority output hygiene: remove only renderer-owned stale dossiers, or publish a clean generation/manifest that clearly marks old dossiers outside the current dataset. Current matrix links do omit the missing row; the stale dossier itself does not disclose its exclusion. |

R1–R4 merit correction before treating all output views as mechanically faithful. R5 is a smaller stale-artifact issue. The probes distinguish altered axis identity, inconsistent attribution and literal output generation from source-claim semantics. They make no requirement that an arbitrary filesystem failure support a transactional multi-file commit; R1's failure is specifically a deterministic malformed-field error which a complete pre-render validation/construction pass can catch.

The six existing tests leave these boundaries untested: typed list items and other contract container types; full 23-axis ordering; duplicated group representations; nondefault study depth and reserved link characters; successive complete/draft generations; and render failures after validation. Focused owned tests for corrected behavior would provide useful oracles. Extra corpus-wide semantic re-review or execution of archived products is unnecessary for these renderer findings.

One additional valid citation defect remains, reported to the root for correction.
