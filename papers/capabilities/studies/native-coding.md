# Native coding agent source study

Pinned source inspection only: references and tests were read, never executed. Row evidence anchors identify actual inspected mechanisms.

## Kaagum

Guile implements the harness; the model is not given a Scheme kernel. `tools/base.scm:226–231` exposes read/list/search and explicitly leaves writing TODO. ACP sessions retain messages, pending call IDs and permissions; `tea.scm:202–237` continues after pending calls complete. `964–1018` executes effects synchronously before more input. Therefore multiple session records do not establish concurrent work, and cancellation at `512–528` cannot interrupt an executing HTTP/container effect. Containers drain stdout before wait (`container.scm:33–55`), avoiding the full-pipe deadlock, but stderr is not captured. Optional fsynced ACP tracing is crash-durable text, not a complete original audit. The sole inspected test checks a typed argument error.

For Arconaut, this small reducer/effects boundary is worth comparing; its blocking executor demonstrates why a protocol and cancel flag alone do not supply live steering.

## OxideAgent

The Rust/Tokio manager genuinely creates distinct worker tasks and bounded mailboxes (`multi_agent_manager.rs:89–173`). Operator focus routes input to an active worker, but model tools remain only file read/write, synchronous shell and startup-discovered MCP. Addressed `send_event_to_agent` is a harness API, not a model-facing live-colleague action. A busy worker awaits chat/tool completion before consuming more mailbox events (`250–342`); no interruption channel was established.

Two material source defects delimit feature claims. `orchestrator.rs:239–250` announces a model switch while leaving the worker’s captured `agent_model` unchanged. `multi_agent_manager.rs:485–554` executes preapproved tools and records results as user prose, whereas only the approval handler (`556–695`) queues continuation. Thus standing authorization may change continuation behavior. These are source-traced concerns, not executed failures. Shell success returns stdout alone; log startup truncates prior diagnostics. Chat persistence and event timestamps do not produce a comprehensive original audit. The permission “concurrent directory changes” tests isolate distinct TempDirs; they cannot establish safety for competing writes to the same permission file.

Arconaut should test authority-independent continuation and actual busy-target message/cancel delivery as direct properties, rather than count workers or UI switch notifications as proof.

## Prime Agent

This pinned revision is a Rust port with a per-session CPython runtime. Its shipped provider-visible tool is **ipython** (`pa-cli/prompt_command.rs:113–124`); file access, shell execution, child creation, mutable harness entries and host skills are composed inside Python. The core loop explicitly polls steering/follow-up/continuation hooks and emits paired results (`pa-agent/agent_loop/run.rs:30–263`). Sequential kernel cells can start persistent BashHandles and independently modeled RLM children. Foreground awaited shell cancellation kills its process group; accessing a background handle releases it from cell cancellation, while kernel teardown still owns cleanup (`rlm/bash.py:954–973`).

Unlike model selection alone, `agent_message.send` is genuine role-addressed family communication. The Rust daemon attempts a direct peer transport then supervisor fallback, with no blind replay of non-idempotent commands (`agent_messaging.rs:227–303`). An inspected worker test specifically checks busy-target queued delivery and queuedAt (`worker/agent_message_tests.rs:204–222`). Ingestion supports pause/capacity; the Rust port explicitly says its displayed token-bucket limits are not enforced (`agent_message_ingest.rs:1–13`), a contract deviation that deserves a matrix limit rather than transferring TS semantics.

Model-requested compact/refine wait until the settled turn boundary (`agent_engine/turn/boundary.rs:33–128`). Refinement is a real plan/re-read/apply/persist/rollback mechanism over memories, prompt notes, skills and subagent specs, with auto-review defaults; it is not executable self-compilation or a measured autoresearch loop. Snapshot continuity is similarly scoped: 16MiB per variable and256MiB aggregate, skipped unpicklables/oversize values and no live socket/process identity. Compaction can remove oversized live variables and tells the model (`session_engine/ipython_state.rs:180–227`). `/reload` refreshes settings/auth/MCP per use, not executable code. Diagnostic budgets/rotation and transformed session records do not establish a complete original audit.

For Arconaut, Prime is a strong comparator for compact model ergonomics, explicit process ownership and boundary-activated model changes. Its owned per-session kernels contradict our intended shared-service consumer boundary; that difference should remain explicit. The key next comparison is whether our experiment governance can couple definition changes to real failure-class oracles and retain enough original state for repair.

## Codex

The current pinned Codex core is Rust/Tokio; it also contains a real embedded V8 code-mode runtime, not merely a JavaScript package wrapper. Native terminal execution resolves a selected local or remote environment and returns process handles for `write_stdin`. The tool future keeps the exact StepContext that advertised its tool list (`tools/parallel.rs:44–164`); next-step changes validate task identity and authority before activation (`session/step_activation.rs:297–378`). This distinction matters for our deferred-change rule: new settings can govern the next sampling step while pending old calls retain their contract.

Code mode builds a fresh V8 isolate/context per cell (`code-mode-runtime/runtime/mod.rs:175–235`), offers nested tools and explicit serializable store/load, and can yield a cell ID for later wait. It is code composition with state primitives, not an arbitrary persistent interpreter namespace. V2 collaboration preserves canonical task paths and distinguishes QueueOnly `send_message` from TriggerTurn `followup_task`; an inspected test rejects a hidden interrupt argument and checks no interrupt Op was emitted (`multi_agents_tests.rs:1858–1920`).

Managed compaction distinguishes manual/pre-turn from mid-turn context reinjection and preserves checkpoint metadata; model `new_context` is a separate fresh-window request, not summarization or environment reset. The optional rollout trace is richer than saved chat: separate original request/tool/runtime/terminal/compaction payloads support a reduced graph. Nevertheless `rollout-trace/inference.rs:83–91` explicitly stores completed/interrupted output summaries rather than every raw stream delta, and rollout persistence filters classes. Thus original audit is materially limited. `/feedback` is operator log submission, not our model rageshake.

Useful Arconaut comparisons are exact advertising-context ownership, separate queued-message/wake/interrupt semantics, remote executor consumption, and payload-versus-view separation. None establishes executable refit continuity or model-governed experiment validation.

## Open Interpreter (current Rust lineage)

This is a Codex-derived Rust distribution, distinct from the original Python project. I byte-compared the inherited handler/audit files used in this dossier and separately inspected changed loop/request/adapter paths; new Codex behavior was not presumed to exist merely because both share names. Its distinguishing mechanism is native harness emulation: request routing shapes prompts/tool schemas and response postprocessing for compiled Kimi/Claude/ZCode/Qwen/etc. strategies (`harness/routing.rs:57–155`, `harness/request.rs:46–137`). `/harness` selects these compiled strategies; it does not load the real vendor implementation or let the model arbitrarily replace the scheduler.

Plan-mode aliases return guidance strings. `TaskStop` writes Ctrl-C then unconditionally announces successful stop (`1161–1196`), without proving process death. These counterexamples are useful for Arconaut’s action/result contracts. Core continuation drains mailbox after sampling/tool settlement; inherited V2 messages distinguish queued send from wake-on-idle follow-up.

Optional V8 code actions are still fresh-isolate computation with explicit serialized storage. Inherited optional audit tracing explicitly omits raw inference deltas. The provider-free mock SSE shell test checks the second request’s actual result text and exit status; route tests are discriminating transport oracles, not proof of equivalent vendor harness performance.


## pi-agent-rust

This is a Rust/asupersync agent with several distinct computation domains, not a JS event-loop agent merely packaged as a binary. Main imports and approval contract are in `src/main.rs:24–128`; the run loop in `src/agent.rs:3180–3315,4062–4135,4910–5259` validates owning input surface, constructs extension-rewritten/redacted provider context, dispatches compatible effect batches concurrently, and preserves tool-call order with explicit skipped/aborted result messages. A monotonic elapsed budget checked at turn boundaries does not guarantee interruption of arbitrary code already running.

The native catalog (`src/tools.rs:5440–5609`) includes conventional filesystem tools, bash/jobs, eval, hub, subagent, media/browser/debug/GitHub/LSP operations and host-coupled ask/todo/plan. Its `eval` is genuinely persistent: Python has an owned subprocess namespace, while JS has a dedicated QuickJS thread and promise pump (`src/eval.rs:32–586`, `src/eval/js_kernel.rs:1–82`). Python timeout kills the process and loses namespace state; JS interruption can preserve globals. The module's opening comment describing JS as future work is stale: actual dispatch and state/timeout tests implement it. Kernel code can do what the host language permits, but the named tool bridge whitelists only read/grep/find/ls. Neither kernel is a standing database or executable refit mechanism.

The project memory bank is separate SQLite machinery: facts/lessons/search/citations and session-shared exact values, with row/index/audit mutations in one transaction and bounded snapshot-conflict retry (`src/memory.rs:1–25`, `src/memory/transactions.rs:30–81`). Model `learn` and `manage_skill` really persist reusable lessons and edit agent-owned skills (`src/tools.rs:8373–8570`); user/project precedence and managed markers constrain this agency. This is an instructive self-programming slice, with no traced measured autoresearch loop or harness recompilation continuity.

`subagent` accepts single, bounded parallel or sequential chain tasks, schema-validated output, named model-bearing definitions and optional worktrees. The model-visible `hub agent` dispatcher can inspect roster/redacted transcript, send steering and manage child lifecycle (`src/subagents.rs:334–392`, `src/tools.rs:9054–9136`). Disk steering append precedes the accepted sequence/inbox update (`src/agent_hub.rs:303–353`). Busy/torn queues reject rather than silently acknowledge; the torn-frame test verifies retained bytes and sequence, then exact retry order. Delivery occurs between turns. Parent-supplied sender labels and bounded redacted histories are weaker than an authenticated, complete shared colleague conversation.

The other hub surface supervises PTY services with readiness regex/port gates, incremental log cursors, later input, restart and detached survival; jobs resolve owning session identity at each call (`src/hub.rs:1–79`, `src/tools.rs:8697–8798`, `src/jobs.rs:1–95`). This is useful lifecycle machinery, but its default role owns resident computation, opposite Arconaut's intended customer boundary. An external service interface could borrow these descriptor ideas without selecting this runtime as a dependency.

Compaction supports summary, instantaneous output dropping (`shake`), extension cancellation/replacement and quota-bounded background preparation (`src/agent.rs:14110–14127,14755–14870`, `src/compaction_worker.rs:1–41`). Context hooks can replace outbound message lists. Saved parent-linked session entries are richer than flat chat, but the inspected event inventory and redacted provider path do not establish an original everything log. Resource `/reload` refuses active processing; extension replacement constructs a candidate then cleans up active streams and cold-swaps shards (`src/interactive/commands.rs:3920–4008`, `src/extensions.rs:11790–11880`). Session-control mailbox transfer preserves unclaimed inputs and identities after a finished turn, not active provider/kernel/executable state across rebuild.

The unusually relevant complaint-looking command is `/omfg`: an operator text grievance becomes a project JSONL record and an active stream abort/retry rule (`src/interactive/workspace_reports.rs:89–126`, `src/stream_rules.rs:615–682`). It does not capture agent state or expose a model-everywhere complaint contract. Arconaut should separate complaint admission from immediate behavioral patching. Read oracles are materially specific: cross-cell JS state/interrupt preservation, torn queue retry atomicity, and trusted versus untrusted resource reload. They were not run; broad swarm and storage testing remains outside this dossier's bounded trace.


## Goose

The inspected CLI/core uses Rust and multithreaded Tokio (`crates/goose-cli/src/main.rs:19–65`). `Agent.reply` selects an explicit state-machine argument, otherwise continuing the older streaming loop (`agents/agent.rs:2079–2174,2720–2785`). The optional path exports a serious reusable `StateMachine`/`Operation`/`Inference`/effects protocol: first applicable operation supplies effects, an effect handler persists them, and a session loader supplies the next state (`crates/goose-agent/src/machine.rs:15–155`). Goose's actual ordered steps remain compiled/internal and the environment flag defaults off (`state_machine/mod.rs:1–81`, `agent.rs:1646–1768`). This is stronger programmability for an embedding author than a recipe prompt, but not model-controlled hot turn replacement.

Provider preparation records the actual advertised tools on assistant requests, then extension execution combines response/notification streams and persists message effects (`state_machine/ops_llm.rs:119–168`, `ops_toolcalling.rs:897–985`, `session.rs:30–133`). Developer actions are write/edit/shell/tree/read_image. Shell captures structured stdout/stderr, exit and truncation information, live notifications, timeout and immediate-child cancellation; output drain is bounded to 500ms (`platform_extensions/developer/mod.rs:108–254`, `developer/shell.rs:554–665`). A shell action is not a writable, identity-bearing standing process service. The TypeScript/bash code-mode extension routes discovered current tools through pctx and propagates a child cancellation token with a bounded callback drain (`code_execution.rs:116–187,215–355`). Cached schema-derived interface state does not establish a persistent kernel namespace; pctx internals were not available in this trace.

Two collaboration mechanisms deserve separation. `summon` delegates an independent context, optionally another provider/model, asynchronously with task ID and load/wait/peek/cancel. Its description expressly says delegates cannot coordinate. Actual dispatch refuses nested delegation and sets children to Auto because parent action-required forwarding is unavailable (`summon.rs:79–106,700–795,1345–1420`). The orchestrator can list/view/start/message/interrupt sessions, but start inherits the parent's model and send rejects a busy target before running/awaiting the target reply (`orchestrator.rs:82–106,502–636`). This is real cross-session communication, with less freedom than durable IRC-style messaging while colleagues work. It should not be conflated with either provider selection or parallel delegation.

Recipes include parameters, extensions, settings/model, output schemas, retries and sub-recipes; optional configured scheduling exposes create/list/update/pause/resume/remove/run-now and produced-session inspection (`recipe/mod.rs:40–130`, `agents/schedule_tool.rs:76–120`). Parent models can search and enable/disable configured extensions; subagents cannot, and the manager cannot remove itself (`ext_manager.rs:150–232,299–350`). Interface cache invalidation follows tool-schema hash changes. This provides useful agency over programs under operation, without evidence of a governed executable improvement experiment or recompile continuity.

Compaction waits for complete tool-pair responses and counts results not yet reported in model usage. Its storage transaction changes old message visibility and inserts new summaries, retaining old content (`ops_compaction.rs:51–88,178–235`, `session/session_manager.rs:2016–2070`). `chatrecall` queries saved chat/date filters or first/last three session messages. Retention is promising for repair, but not a full original audit: content telemetry is optional and reconstructed message finish reasons expressly differ from provider finish reasons (`gen_ai_telemetry.rs:10–43`). Exact request/stream/program lineage and model repair authority remain unestablished.

The read source tests are discriminating: held mock responses prove FIFO steering appears in the next provider input and survives compaction, cancellation retains steering for exactly-once resume; synthetic delegate streams prove child-tagged notifications precede completion; direct calls prove session-type restrictions on dynamic extension management. No tests were executed and these oracles do not establish arbitrary provider/tool cancellation, process-tree lifetime or kernel persistence.


## Crush

Crush is a Go/goroutine/context agent whose model/tool iteration is delegated to Fantasy. The inspected host code still gives useful precise behavior: `sessionAgent.Run` serializes busy/accepted/active decisions under a per-session lock, registers the cancellation identity before assistant creation, and guards cleanup against deleting a newer run (`internal/agent/agent.go:605–706`). Each step refreshes current tools and drains queued prompts. Unidentified follow-ups can fold into steering; RunID-bearing prompts remain separate turns with their own terminal completion. Accepted-run sequences let a cancellation cover work accepted but not yet active (`agent.go:844–913`, `dispatch_cancel_test.go:71–124`, `queued_runid_test.go:78–162`). These are concrete fault classes for Arconaut's configurable turn/workflow admission, not abstract claims that cancellation works.

The actual coordinator catalog covers view/write/edit/multiedit/search, bash and background jobs, task delegation, web/resource tools, LSP operations, questions/todos/config information/logs and discovered MCP schemas (`coordinator.go:876–969`). Write rejects a file observed modified since its last read, then asks permission and writes bytes (`tools/write.go:56–142`); its second-resolution modification-time guard is not an atomic shared-writer reservation. Bash starts a fresh interpreter-backed shell, immediately or after a default 60-second auto-background threshold. `job_output` reads/waits and `job_kill` cancels the handle (`tools/bash.go:166–388`, `shell/background.go:45–154`). The process-global registry has handles but no traced per-session ownership validation. A skipped approval prompt does not remove installed static command blockers.

The model's `agent` tool accepts only a prompt, creates a separate task session and awaits the host-configured task agent, accumulating cost (`agent_tool.go:18–72`, `coordinator.go:1660–1733`). Parallel designation and separate sessions do not establish a live colleague room or model-chosen provider for each task. External MCP channels are a separate supporting path: opted-in validated notifications are published with must-deliver semantics and backend ordered routing, with tool-based replies (`tools/mcp/channel.go:157–205`, `backend/channels.go:23–95`, `channelreply.go:19–46`). Initialization/dispatch failures still log and drop a workspace push. This supports external live messaging, with a bounded loss/authority contract Arconaut should make explicit.

Hot configuration is real: reload builds a candidate, validates hooks, preserves instance-selected model overrides and rolls back on failure (`config/store.go:1295–1369`). Per-step tools and a current-model callback can change subsequent requests. Top-level shell hooks can rewrite inputs, deny/halt, preapprove or add result context; errors proceed and child sessions skip hooks (`hooked_tool.go:17–97`). Executable configuration and hook programs provide workflow primitives, not unrestricted model replacement of the Go/Fantasy loop or recompile continuity. The reload test deliberately supplies invalid and nonterminating crushrc code and asserts a bounded cancellation response plus preservation of old config, a useful independent state-retention oracle (`reload_crushrc_test.go:29–105`).

Compaction creates a persisted summary message and switches a summary pointer; outbound history reads the retained summary tail (`agent.go:1411–1464,1514–1552,1792–1814`). Saved transcript is not an original audit: retry resets partial streamed text and invalid tool JSON is sanitized before persistence (`agent.go:973–1068`). Model `crush_logs` returns only bounded, redacted recent diagnostic entries (`tools/crush_logs.go:20–116`). Precise model repair, captured-state complaints and governed self-improvement remain unestablished. Tests were read, never executed; Fantasy internal scheduling and full LSP/network/OS-isolation behavior are outside this trace.


## Forge-Adulari

This Rust/Tokio Forge is a distinct project from Tailcall ForgeCode. This contains synchronous interpreter starvation without putting the outer scheduler on JS, but it offers no persistent realm namespace. It should inform an owned Arconaut workflow interface rather than select an implementation dependency.

Persistent child follow-up (`send_to_agent`) reloads a previously spawned child's history/persona. Separate daemon-only `message_session` addresses live fleet peers, persists sender/recipient/mode before attempted delivery, and distinguishes backlog follow-up from next-boundary steer priority (`subagent.rs:209–242`, `orchestration.rs:180–244`, `fleet.rs:1–96`, `forge-cli/.../daemon_fleet.rs:16–73`). Bare CLI does not have that host. This is real colleague messaging, unlike provider choices or parallel task returns. Its mid-turn inbox drains only at legal boundaries; a deadline can ask one more model turn to revert unverified changes, so it is not a refit quiescence guarantee.

Standing memory is internal SQLite, scoped project/global with duplicate/salience curation and bounded rows (`forge-store/src/memory.rs:1–68`); model `remember` persists typed facts. Compaction aligns retained tail to tool rounds and retains originals; `uncompact` reactivates them and rewind restores file snapshots using stable DB sequences (`compaction_policy.rs:465–522,701–734`, `session_history.rs:7–69`). These are actual repair mechanisms exposed to operator/program APIs, not yet ubiquitous model-directed repair of any corrupted context.

The provenance/replay system needs skeptical interpretation. CLI bridges expose only tool summaries, not raw output (`model_stream.rs:31–85`). Replay filters visibility and guesses success from an error-prefix convention (`replay.rs:1–70`). Continual Harness refinement really validates, applies and journals model-proposed prompt/skill/subagent entries with rationale/expected outcome and rollback (`refinement.rs:31–80,194–249`), with immutable base system prompt and separate memory ownership. `/duel` implements same-task model comparisons in up to three isolated worktrees with test/diff/time/cost and operator-selected winner/routing feedback (`duel.rs:1–104`). This is substantive experimental machinery, still distinct from model-governed executable self-improvement. The supplied rebuild script kills MCP processes before/after compilation and relies on respawn; it transfers no live context to an outpost (`scripts/rebuild.sh:1–23`).

Read workflow oracles distinguish actual host overlap (two 50ms calls under 90ms), runaway synchronous loop interruption and long await exemption. The timing test can suffer scheduler-load false failures. A prose-only phantom-edit test proves repeated requests and explicit warning, not the README's universal assertion that the harness never reports phantom success. All tests were read, not run; large provider/device/assay/OS-isolation surfaces remain bounded gaps.


## ForgeCode (Tailcall)

This is a Rust/Tokio implementation, distinct from Forge-Adulari. `ForgeApp.chat` resolves agent/provider/tools and builds compiled hooks (`crates/forge_app/src/app.rs:60–197`). `Orchestrator` normalizes outgoing context, streams a model reply, runs actions, appends paired results, persists context and repeats (`orch.rs:201–475`); the OpenAI-compatible adapter actually serializes a request into HTTP eventsource (`provider/openai.rs:214–257`). Finish with no actions yields; `followup` yields; configured error/request limits yield. End hooks that add messages resume the loop.

Native exact names are `read`, `write`, `fs_search`, `sem_search`, `remove`, `patch`, `multi_patch`, `undo`, `shell`, `fetch`, `followup`, `plan`, `skill`, `todo_write`, `todo_read`, `task`, plus named agent tools and MCP discovery. Task accepts agent/tasks/session_id, launches concurrent new or resumed child conversations and returns final text/conversation identity (`tool_registry.rs:106–195`, `agent_executor.rs:50–145`). This is useful delegation, without a live peer messaging/observation protocol. Native ordinary tools run sequentially; task groups run together and final result order is restored (`orch.rs:59–166`). Shell concurrency is narrower still: one shared async mutex serializes all commands, inherited stdin may interact with terminal, and direct child kill-on-drop plus captured streams provide cancellation/result handling (`forge_infra/src/executor.rs:26–150`). No ongoing command handle is exposed.

Stream ownership matters. Ctrl-C drops the UI future (`forge_main/src/ui.rs:379–425`), whose `MpscStream` aborts its producer task on Drop (`forge_stream/src/mpsc_stream.rs:34–40`). This bypasses the post-run 'always save' block in `app.rs`; successful iteration saves remain, but abort is not a finalization transaction. The virtual-time test only establishes that the task's completion flag stays false. It proves neither final save nor descendant-process termination.

Compaction is pure structured transformation, despite configurable compaction-model fields: select retention/eviction range, deduplicate/trim operations, render a summary, splice away originals, transfer usage and last reasoning (`compact.rs:39–169`). SQLite upsert replaces current context rather than keeping an immutable event journal (`conversation_repo.rs:46–76`). Tracing omits request payload and records selected usage/errors, so neither chat nor dump establishes original audit. Operator JSON export/import supplies a repair primitive only when an earlier useful snapshot exists. Session configuration invalidates cached agents for subsequent chats; compiled hooks are a programmability primitive, not model-loaded executable turns or refit.

The pending-todo oracle is a revealing qualification: it asserts one reminder and permits a second Stop to finish with the same still-pending todos (`orch_spec/orch_spec.rs:605–658`). It is not a completion-proof mechanism. Compaction tests preserve aggregate usage through destroyed messages; config tests deliberately preserve a default agent retention zero overriding workflow ten. These oracles make policy/default/ownership questions visible for Arconaut, without endorsing the policies.


## Stakpak

Stakpak's Rust/Tokio source has two actual paths. The interactive/async CLI uses `AgentClient` completion hooks and saved checkpoints, then invokes MCP actions sequentially (`mode_async.rs:487–725`, `client/provider.rs:178–224,830–914`). Interactive stream processing explicitly races cancellation and calls `cancel_stream` (`mode_interactive.rs:1398–1456`). The server/autopilot instead creates a session actor and feeds native `agent-core.run_agent` (`session_actor.rs:43–328`). The OpenAI adapter actually posts converted JSON, confirming local native inference rather than treating all behavior as an opaque service (`libs/ai/src/providers/openai/provider.rs:489–535`). The row keeps claims scoped to the appropriate path.

The MCP action inventory includes local/SSH file viewing and mutations; synchronous and background commands; task inspect/wait/cancel; optional subprocess subagents/resume; docs/skills; password/webpage utilities; optional Slack read/thread/send. `ask_user` is a TUI intercept whose actual server handler returns INTERACTIVE_REQUIRED. `search_memory` is commented out despite memory mentions. Background local processes have null stdin and their own process group, with tasks in a global in-memory manager. Cancellation removes the task and kills/aborts it; manager Drop signals termination, not preserve/pause (`task_manager.rs:278–303,573–594,650–681,927–940`). This differs materially from Arconaut consuming shared fabric. Dynamic children choose model/tools and run the same CLI as tracked subprocesses; resumed child work launches a new process from a saved checkpoint, not a live peer messaging interface.

Server session coordination reserves Starting under lock and rejects duplicate or stale run IDs (`session_manager.rs:48–110,146–224`). Steering between action phases pairs unstarted calls with skipped results; follow-up waits for finish; SwitchModel changes subsequent requests. Cancellation has an important limit: `cancel_run` only flips a token, while inference.generate, retry sleep and the pending-approval `command_rx.recv` are not raced against that token (`agent.rs:137–236,659–707`). MCP response waits are cancellation-aware. Delayed cancellation/stalled approval is an inspection inference requiring an experiment, not an executed failure report.

The server's compactor is explicitly **PassthroughCompactionEngine**. Overflow recovery returns unchanged messages, subtracts turn count and restarts, creating a source-inferred no-progress loop risk. Actual request shaping is `BudgetAwareContextReducer`: it works on a copy, sanitizes tool pairs, replaces older assistant/tool text with placeholders, retains user/system content and stores a monotonic trim boundary. Original vectors remain checkpointed. This is valuable separation, but there is no model selective context-repair interface, and estimated trim thresholds are not exact provider token accounting.

Checkpoints have versioned envelopes and latest-file rename replacement. The event log is a bounded in-memory ring with per-session cursors and explicit gap/refresh-snapshot response (`event_log.rs:35–151`). Core TextDelta/ThinkingDelta are emitted from an already complete generate reply, not original provider chunks; rendered MCP text is sanitized and nontext omitted. These are useful client observations, not complete permanent audit. Gateway routing picks one conversation by DM/group/thread; Slack transport does not itself provide independent live model peers.

Autopilot cron/check/profile schedules are real standing orchestration. Config reload retains current schedules on load errors, rejects DB-path change and reconciles jobs; schedule singleton checks skip an already-running run, but DB-check error proceeds (`watch/commands/run.rs:435–583`). This is useful activation machinery without a universal end-of-affected-workflow boundary. Tests establish concurrent single-run reservation, replay gaps and estimator-based request trimming. A named 'drop kills child processes' test has no post-drop liveness assertion: it observes Running before Drop, waits, cleans a marker. The matrix records that oracle weakness rather than inheriting its name as a guarantee.


## VTCode

VTCode’s primary engine is Rust and multithreaded Tokio (`src/main.rs:83–117,278–294`). The npm distribution is not evidence of a JavaScript core. Provider `codex` selects a separate App Server session runtime (`src/agent/agents.rs:125–183`); this dossier traces the native unified loop. Each iteration drains steering and pending model/effort changes before building a captured request (`turn/turn_loop.rs:913–940`, `turn_processing/llm_request/mod.rs:162–230`). A nonstreaming provider future is explicitly raced with cancellation (`433–475`), and the concrete OpenAI path submits an authorized Responses request (`vtcode-llm/.../generation.rs:286–349`). Pre-tool hooks may rewrite arguments, which are revalidated before policy; prepared calls dispatch individually or in readonly parallel groups. Results enter model history before UI rendering and then select continuation or a compiled primary-agent handoff (`tool_pipeline/execution_run.rs:125–256`, `tool_outcomes/execution_result.rs:150–241`). These paths substantiate a real native loop, not README-derived feature claims.

The public action surface needs care. `exec_command` creates owned pipe/PTY handles; `write_stdin` implements write/poll/wait with deadlines that preserve ongoing work. Its broader description mentions inspect/terminate/close, but the actual dispatcher does not implement those actions (`tools/registry/executors.rs:647–670`). Old unified action names and `read_file/list_files/write_file/edit_file` are expressly removed from public routes (`assembly.rs:96–139`); structured code search, patch editing and shell access remain. Native memory is persistent note files under `/memories`, not a general standing DB. `cron` schedules prompts until the current process exits. A hidden code action generates an MCP/builtin SDK and runs a fresh Python/JavaScript process; it does not supply a resident kernel, and “harness kernel” is a compiled tool/mode filter (`core/agent/harness_kernel.rs:11–118`). Traditional skill activation really refreshes the session tool catalog; an already-active skill returns cached content (`tools/skills/mod.rs:104–151`). This supplies workflow composition and hot tools, with a precise activation boundary, rather than a programmable replacement turn.

Parent/child control is concrete: `agent` exposes spawn, separate managed subprocess, send_input, resume, wait and close, with model/effort and fork-context choices (`executors/subagents.rs:12–112`). Noninterrupt messages should queue until the child finishes; interrupts abort the task and replace queued prompts. A source-inferred race deserves an independent oracle: the first queued input marks a running child `Waiting`; another input in that state follows the restart branch. `restart_child` unconditionally launches a new loop, and launch overwrites the stored JoinHandle without checking or cancelling the previous task (`controller_spawn_run.rs:194–243,1058–1077`, `controller_child_loop.rs:40–112`). Both loops can consume/update the same child record (`types.rs:421–470`). No execution was performed, and synthetic cascade tests do not exercise this busy-child sequence. Background restoration preserves desired state/record identity and respawns missing subprocesses; it does not reconnect an old process. Automatic worktree reconciliation uses `HeuristicDiffVerifier`; the separate public Rust verifier API runs a bounded LLM child but is not that default path (`controller_verify.rs:49–135,153–200`). None establishes governed harness autoresearch.

Compaction has explicit native/local strategy dispatch, unchanged/growth guards, opaque provider-output preservation, response-chain reset and boundary events. A failing mock preserves exact original history, while recovery tests retain an exact current-turn suffix (`turn/compaction/tests.rs:1502–1529,1732–1788`). When dynamic persistence is enabled, original rendered context is saved and linked for shell recovery (`vtcode-core/src/compaction/memory_envelope.rs:528–587`). That is useful context-repair machinery, but it is optional, text-converted and retained in a bounded file set; it is not original typed or provider-wire state.

Production auditing is stronger than the optional trajectory logger: a canonical store is opened before the session, orders admissions, applies bounded backpressure, isolates optional export failures and reports drain errors (`inline_events/harness.rs:83–108,184–216,325–379`). The decisive limit is retention. The canonical sink uses the 10,000-event default; eviction replaces original completed-turn bytes after saving counts, kinds and selected facts (`vtcode-memory/src/event_log.rs:21–36,580–605,1054–1076`). `session-store pack` can verify retained-file hashes, not complete original capture. The 3,253-event drain test checks accepted-event cardinality and unique IDs; it cannot prove observations never omitted or originals never evicted. `/feedback` opens a GitHub issue chooser without model-state capture.

Hot model changes activate at the next request, potentially within the current turn; layered config reload preserves the previous valid state on errors. Update relaunch retains original argv/cwd and Unix-execs a replacement, without an outpost or newly injected conversation identity (`main_helpers/relaunch.rs:48–111`). Normal finalization can detach provider-backed memory work after five seconds (`orchestration.rs:2630–2675`), so this is not Arconaut’s required refit quiescence. VTCode offers strong individual lifecycle and persistence mechanisms; its ownership transitions, original retention and activation boundaries require separate design decisions.


## Cross-family findings and Arconaut discriminators

These twelve references share file/program/provider operations but differ substantially in who owns continuing work. A child ID, PTY handle, checkpoint, mutable configuration and compiler-produced binary establish different things. The matrix should retain those distinctions rather than compressing them into one “extensible” or “persistent” label. Every assertion below is anchored by the corresponding completed row and dossier; none is runtime conformance evidence.

| Mechanism | Useful native examples | Boundary that matters for Arconaut |
| --- | --- | --- |
| Computation state | Prime’s persistent CPython kernels; Pi Rust’s owned Python process and dedicated QuickJS thread; Codex’s fresh V8 cells with serialized store/load | Resident interpreter state, explicitly serialized values and external service handles have different continuity and ownership. Arconaut consumes shared compute; it need not own each kernel. |
| Live colleague interaction | Prime’s child mailboxes/receipts; Pi Rust’s disk-first agent hub; Codex’s queued send versus followup-triggered turn; Adulari’s fleet session messages | A selectable model is not communication. A delivery receipt, durable record, triggered turn and applied steering are distinct events. Busy-target semantics and ownership must be explicit. |
| Workflow expression | Adulari’s QuickJS workflow programs; Crush’s executable configuration/hooks; Goose’s recipes and compiled operation state machine; VTCode’s skill activation and cron | Program composition can be useful while the main turn remains compiled and fixed. Explicit scheduling/admission and mutation boundaries determine which programs can be changed midoperation. |
| Context recovery | Goose preserves superseded messages via visibility changes; Adulari supports uncompaction/rewind; VTCode links conditional original-text artifacts | Reusing retained content is not restoring an original raw provider request or repairing lost provenance. Model repair requires both retained material and a defined mutation/merge authority. |
| Audit persistence | Pi Rust’s durable mailbox append; VTCode’s authoritative backpressured event sink; Codex rollout records | Each records a particular subsystem. VTCode evicts original event bytes, Codex excludes raw streamed deltas, Adulari truncates tool output before DB insertion. Complete original audit was not established for any inspected harness. |
| Change activation | Codex captures tool-step context; VTCode activates model settings at next request; Crush validates candidate config and preserves old config on error | “Hot” describes several boundaries. Arconaut’s default after current turn/affected workflow, plus explicit interrupt-and-activate, needs a first-class activation operation and recorded outcome. |
| Executable replacement | Adulari rebuild script; VTCode updater relaunch; checkpoints and desired subprocess restoration in several agents | Recompile/restart is not outpost continuity. No inspected source establishes the complete Arconaut protocol: no owned active programs/provider calls, paused standing work, context handoff, observed rebuild, recovery and reinhabitation. |

Several failures are especially valuable counterexamples. Oxide’s preapproved path records a result without the continuation enqueued by its approval handler, and its displayed model switch leaves a worker’s captured model unchanged. ForgeCode cancellation drops its producer and can bypass the final persistence branch. Stakpak’s native server flips a cancellation token without racing a pending provider/approval wait; its passthrough compactor may retry with unchanged overflowing context. VTCode can launch another loop for one child record after two noninterrupt follow-ups. Kaagum processes synchronous effects before reading further input. These are source-traced or source-inferred concerns with the confidence and limitations stated in their rows; they are not observed bugs from executing the references.

The better tests attack externally distinguishable states. VTCode waits for a real child exit status after termination. Crush holds accepted work and verifies cancellation sequences do not affect a newer run. Goose holds mock responses and inspects exactly which next provider input receives steering. Pi Rust exercises torn mailbox frames and kernel timeout behavior. In contrast, a type-error assertion, nominal return value, count of grouping plans, isolated-directory concurrency test or synthetic closed child status cannot establish live cancellation, shared-writer isolation or absence of duplicate runners. Arconaut’s eventual tests should reserve independent observations for those fault classes.

Five discriminating experiments follow from this unit: hold a provider request and prove interrupt completes without waiting for it; send repeated messages to a busy colleague and prove one admitted run per identity plus exactly-once delivery; compact repeatedly and recover a deliberately omitted fact with preserved original lineage; reload invalid configuration and prove both old behavior and activation boundary; and perform executable refit while observing all owned provider/process handles, external standing services and the outpost’s continuity. These are proposed Arconaut research oracles, not authorization to execute quarantined code. Complaints deserve the same explicit model-state and event contract; the inspected operator feedback URLs/log access do not supply it.
