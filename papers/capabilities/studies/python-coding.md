# Python coding-agent source study

Pinned source and test inspection only; no reference was executed. This cohort covers ten references: mini-SWE-agent, SWE-agent, GPT Engineer, Devika, Trae, DeepAgents, OpenDev, Sweep, Kimi CLI and Mistral Vibe. OpenDev has migrated to Rust and Mistral includes a Rust experimental core; grouping is catalog convenience, not a language claim. The three operator-facing Python systems are completed in [Python operator interfaces](python-operator-interfaces.md). The two hosted/workspace systems are completed in [Hosted workspace agents](hosted-workspace-agents.md). Together those reports cover the fifteen-reference original Python cohort; the five separately owned dossiers are not missing from this study.

## mini-SWE-agent

The complete core is an unusually legible synchronous Python loop: `run` resets messages, `step` calls query then actions, flow exceptions add recovery/exit messages, and each iteration saves (`agents/default.py:86–171`). CLI selects replaceable model/environment/agent classes; arbitrary class import and duck-typed protocols are actual host programmability, not hot model access to loop definitions (`agents/__init__.py:15–30`, `__init__.py:43–85`). Native model action is `bash(command)`. The tool adapter accepts several bash calls and executes them serially; the older text adapter instead enforces exactly one configured action fence (`models/utils/actions_toolcall.py:11–65`, `actions_text.py:17–40`). File operations, code execution and unusual OS workflows are ordinary shell composition, not separately governed tools.

Local actions use a fresh `subprocess.run(shell=True)` with merged environment, configured cwd, combined stderr/stdout and timeout. Docker owns a continuing container but starts another interpreter for each `docker exec` (`environments/local.py:12–79`, `docker.py:72–139`). Neither gives a persistent kernel namespace or resumable process handle. A successful command whose first nonblank output line is `COMPLETE_TASK_AND_SUBMIT_FINAL_OUTPUT` raises submission; completion trusts that stdout convention. Interactive human/confirm/yolo modes and whitelist control prompts; Ctrl+C around a step prompts steering and partial observations are added in `finally`. The formatter pads unexecuted calls with paired error results (`interactive.py:101–132,160–219`, `actions_toolcall.py:68–113`). This is a useful small authority/continuation invariant, while real busy-provider/process cancellation remains untested by the inspected mocked interruption test.

The concrete LiteLLM path sends one synchronous request and captures returned response dumps; malformed format errors also carry an unparsed response. Observation metadata keeps full `raw_output` even when model-facing templates elide the middle (`litellm_model.py:49–114`, `actions_toolcall.py:68–113`). However, saved trajectory is a replaced JSON snapshot after each step, not original append audit, and retry/wire events are not captured by this loop. A source-inferred accounting concern follows the failure order: model cost is added to global stats before parsing, but `DefaultAgent` adds cost only when model.query returns. A paid FormatError raises before that return, so its local cost budget can undercount malformed replies. Existing limit tests do not address this sequence. Counters/start time are initialized once, while run resets only messages; rerunning the same object retains budget history.

Roulette/interleaving adapters select different models on successive queries in the same history (`models/extra/roulette.py:13–74`); that is implemented routing, not live colleague messaging. Batch SWE-bench runs overlap independent instances using a thread pool, save predictions and trajectories, and cancel only pending futures on interrupt (`run/benchmarks/swebench.py:134–176,245–271`). This is evaluation generation/support, not a workflow language, model-governed self-improvement or in-flight team control. The trajectory inspector supplies step/full JSON navigation. Managed compaction, standing DB, captured-state complaints and refit continuity were not established in these inspected paths. The timeout test’s independent 111×9 output oracle and malformed-response retention test are useful contrasts with a mocked KeyboardInterrupt: each attacks a specific fault class and none was executed here.


## SWE-agent

The Python core takes one model action per reply, then processes it through a configured parser/filter and a continuing SWE-ReX bash session (`agent/agents.py:1006–1061,1235–1297`, `tools/parsing.py:438–459`, `environment/swe_env.py:168–232`). This is a client boundary: session/process implementation lives in an external dependency, not in this snapshot. Tool installation uploads selected bundles, adds executable bins to PATH and sources install commands; state is read from environment JSON (`tools/tools.py:254–267,292–378`). Default model operations are bash, Anthropic-style `str_replace_editor` and multi-stage `submit`. Optional bundles declare search/window/filemap/image/browser commands through the same generated catalog. The source contract and optional names are recorded without transferring certainty from their schemas to untraced executors.

The action loop has bounded format/blocklist/syntax requery and error autosubmission. Failed queries are kept as trajectory steps but omitted from the successful model history; each completed step saves history, original observation, query projection, state and replay configuration (`agents.py:714–811,1062–1137`). Last-N observation processing constructs an elided projection rather than destroying stored history (`history_processors.py:150–178`). This is useful context-recovery infrastructure. It is not managed model compaction/repair, original provider-wire audit or crash-safe event capture. The model adapter normalizes response text/tool/thinking fields; editor clipping happens before the harness receives output, and trajectory save replaces a file after the step.

Two source limits deserve concrete tests. Command timeout requests backend interruption, but KeyboardInterrupt is reraised. `RunSingle.run` closes the deployment only after ordinary completion, without a finally cleanup (`run_single.py:170–206`); no process-tree/quiescence guarantee follows. The editor’s advertised undo also warrants challenge: `_file_history` parses a fresh JSON dictionary on each getter access, while replacement appends to that temporary dictionary without assigning the setter (`str_replace_editor:350–401,576–590`). Undo then reads another fresh dictionary (`634–645`). The inspected script has no write-back caller, and Path-indexed temporary updates do not establish persistent cross-process history. This is a source-inferred fault, not an executed reproduction.

Sequential retry really selects different attempt configs/models, resets the environment, reviews solutions and chooses a score/chooser-selected result under cost/attempt/accept limits (`agents.py:294–326,409–442`, `reviewer.py:617–658`). The `AskColleagues` name should not obscure its mechanism: the same model samples several replies then compares a synthesized discussion (`action_sampler.py:40–94`, `models.py:783–798`). Neither is live peer communication. Review-on-submit simply emits configured prompts then a patch sentinel; it does not independently validate changes. These search primitives are relevant to autodroit, but do not establish governed executable self-improvement.

Replay extracts old actions and constructs a new ReplayModel/environment, then executes them again (`run_replay.py:94–127,139–171`). It is experimentation/demo reproduction rather than continuity of unresolved provider or shell work. Benchmark threads overlap independent instances and cancel pending jobs while running ones finish; enabled evaluation calls external sb-cli. The inspected scripted-model test precisely distinguishes failed-requery trajectory from successful history, while the history processor test only checks omission/tag counts. Neither proves real backend cancellation, immutable original retention, undo correctness or executable reinhabitation. No reference test or program was run.


## GPT Engineer

GPT Engineer is a staged Python generator/diff-repair system, not a general coding tool-call loop. `SimpleAgent.init` generates code then an entrypoint; `CliAgent` injects generation/improvement/processing callables and chains generated files→launch script→selected execution (`default/simple_agent.py:69–92`, `cli_agent.py:88–111,166–219`). The model produces textual filename/code blocks or unified diffs, which host parsing/applicability correction converts into FilesDict. Incorrect hunks trigger bounded refinement; this proves placement/applicability, not program behavior (`default/steps.py:143–202,298–360`). Default entrypoint execution asks consent, and CLI improvement asks whether to apply changes. Direct host APIs and selected self-heal have different interaction scopes.

AI uses synchronous LangChain invoke through a chosen OpenAI/Azure/Anthropic adapter and streams text to stdout. Nonvision normalization collapses same-role messages and extracts only the first list text block, rebuilding message representation (`core/ai.py:147–205,229–287,345–379`). Clipboard mode exports serialized text and accepts an operator-pasted reply. Preprompts are reread on stage getter calls, a useful prompt-update primitive, while an improvement/refinement loop captures its prompt/messages before retry (`preprompts_holder.py:23–28`). Neither provider choice nor message normalization establishes multi-model live collaboration or managed compaction.

`DiskExecutionEnv` writes files and runs fresh subprocesses. Its `run` reads stdout and stderr synchronously, one line from each, before checking deadline; a silent/stalled pipe can block that timeout, and asymmetric full pipes can deadlock. The loop may stop on poll without draining final output, and timeout/Ctrl+C kills without wait/reap (`disk_execution_env.py:54–114`). Programmatic popen returns a raw handle, not model-owned lifecycle orchestration. The inspected interrupt test asserts only a mocked kill call, and the output test checks popen/communicate mocks rather than this run loop.

`--self-heal` reruns generated application scripts up to ten attempts, feeds failures to the diff-improver, and stops for returncode 0 or 2. It calls unbounded communicate and never changes its timed_out flag (`custom_steps.py:85–122`). That is application autorepair, not measured harness self-improvement/reinhabitation. The benchmark exposes assertion callbacks against files/process/output, but passes benchmark.timeout as communicate’s first positional input, a source-inferred timeout defect (`benchmark/run.py:46–92`). Some functional tests independently require exact generated/changed output files; several complex-diff tests have no assertions or merely print output, and cleanup asserts True.

DiskMemory appends timestamped rendered logs and archives them at startup (`disk_memory.py:288–326`). It is useful saved study data, not complete original request/stream/program audit or a standing query DB. Opted-in human review/telemetry gathers ran/quality/usefulness/comments and may trim oversized logs; it is not model-state rageshake. Managed workflow identity, queued steering, original context repair, hot executable replacement and outpost continuity were not established. No reference program, test or telemetry path was executed.


## Devika

The socket handler creates a new `Agent` and thread for a message; the active-task branch still starts work (`devika.py:76–103`). Initial execution is a fixed planner → monologue → researcher → optional question polling → search/formatter → coder pipeline. Every stage receives the same chosen model (`src/agents/agent.py:36–67,270–360`). Subsequent input is classified into `answer`, `run`, `deploy`, `feature`, `bug`, or `report`. This is useful staged orchestration, with no inspected live colleague protocol or model-programmable workflow interpreter.

Files come from text blocks and are saved by joining model filenames into the project path. The displayed `vim` command is an emulated editing state (`coder.py:68–107`), not a terminal operation. Runner splits commands on spaces and blocks in `subprocess.run`; stderr is captured but omitted from repair prompts and terminal state. A further source-inferred fault is that `run_code` never returns success, so its `retry_wrapper` repeats the entire command batch up to five times (`runner.py:69–198`, `services/utils.py:9–26`). The provider timeout raises inside a `ThreadPoolExecutor` context whose exit waits for the worker, so a timer message does not establish cancelled inference (`llm.py:118–145`). These findings have not been executed.

SQLite stores rewritten JSON chat/state stacks. KnowledgeBase has actual exact-tag add/get methods, but the main search read/write calls are commented out. Mutable latest states, response-content-only transport and missing stderr prevent a complete audit claim. Settings mutate immediately; prompts are read at module import and clients capture their model. Neither supplies the operator's after-workflow activation/refit contract. The secondary browser grammar exists but its inference call omits required `project_name`, while `/api/run-code` is a TODO returning “started.” Source inventory exposes no assertion-based tests; the benchmark marker says not yet. Devika is chiefly a caution against transferring architectural names and UI activity into machinery claims.


## Trae Agent

BaseAgent awaits a fixed numbered step loop, but calls the provider synchronously. The concrete OpenAI-compatible client owns cumulative request history; loop messages are only the next delta. Trajectory recording logs that delta and a normalized reply (`base_agent.py:147–236`; `openai_compatible_base.py:109–215`), so it is not a faithful record of complete provider requests/retries. Rewritten JSON snapshots warn and continue on failed writes. `_finalize_step` marks a failed step completed even when execution remains ERROR.

Native actions are `bash`, `str_replace_based_edit_tool`, `json_edit_tool`, `sequentialthinking`, `task_done`, and optional `ckg`; allowed MCP servers add discovered tools. Completion is intercepted before dispatch: any `task_done` in a response can complete the task and skip all co-issued calls. `must_patch` demands a nonempty patch after removing test changes, not a passing behavioral oracle (`trae_agent.py:228–249`). Local batches use gather while Docker batches deliberately serialize.

Bash owns a long-lived shell, yet each command is enclosed in `( ... )`, so directory/environment mutations do not persist as the description promises (`bash_tool.py:87–189`). Private StreamReader buffers and a sentinel demarcate output. Timeout marks the session unusable but does not kill immediately. Concurrent calls share that shell and buffers without an inspected lock. Close terminates the direct process with bounded communicate; descendant-group termination is not established. Async cancellation bypasses cleanup located after the BaseAgent finally block. MCP keeps only the first text content, and its isError branch leaves default error_code, which can misclassify success (`mcp_tool.py:49–55`, `base.py:219–227`).

CKG is a real model-facing SQLite code index with snapshot reuse and expiry, not a general shared standing database. Thought branches store records/counts without executing workflows. Source shell tests assert echo/errors/restart but never persistent cd/env, concurrent isolation or cancellation custody; completion tests assert empty versus mocked nonempty patches. These are useful baseline oracles with sharply bounded claims, and no reference was run.


## DeepAgents

The primary SDK assembles a LangChain/LangGraph agent with backend files/execute, subagents, summarization and unmatched-call repair (`libs/deepagents/deepagents/graph.py:639–700,863–983`). The actual provider/tool scheduler is an unvendored dependency, not machinery reimplemented here. This dossier scopes claims to that SDK; Code, Talon and ACP in the same monorepo are separate application surfaces not comprehensively traced. Files include native deletion despite older overview prose omitting it. Execute is only supported by suitable backends. LocalShell is fresh `subprocess.run` with cwd/env/deadline and clips combined stdout/stderr before returning; no resident kernel or stable process identity follows from it.

`task` invokes a configured child synchronously/awaited. Children may use distinct models, isolated prompts or effective-history forks; parent receives selected state and last AI text. Fork recursion is refused. Hosted `start_async_task` instead creates a remote thread/run and records stable task identity; `check_async_task`, `list_async_tasks`, `update_async_task` and `cancel_async_task` give model agency over ongoing work. Update starts a new run on the same thread with interrupt strategy. Cancel marks local state cancelled after API acceptance, without an independent observed termination oracle. These are parent/child collaboration operations, not a general peer chat bus. A partially failed remote launch is not followed by an inspected cleanup transaction.

StoreBackend consumes a supplied/context store under caller namespaces across threads, a useful shared-service boundary. It exposes files rather than general SQL. Memory files load only while cached state is absent. Custom middleware replaces entries by name at graph construction; this is expressive programming, not after-workflow hot activation.

Automatic compaction keeps a private summary event selecting the effective model context instead of deleting the full message channel. A separate optional `compact_conversation` tool shares that mechanism. Model `read_file` can reopen rendered offloaded history. This is a strong context-repair primitive with real limits: history offload failures warn and continue; media may become failed placeholders; large tool results are offloaded/projected before entering state; LocalShell already clipped output. Thus “raw log preserved” is scoped to stored message state, not a comprehensive original audit. PatchToolCalls inserts explicit error observations for unmatched calls, conservatively stating they may have been interrupted rather than falsely claiming execution.

Compaction recovery tests impose input budgets, assert unchanged original request/full result offload, and prohibit unchanged or repeated overflow retries. Hosted update tests assert stable task/new run and interrupt strategy through mocks. They directly attack useful claims, but do not verify vendor transport fidelity, remote quiescence or endpoint races. No downloaded program ran.


## OpenDev

This pinned reference has migrated to Rust (workspace version 0.1.9); the Python-family registry grouping is catalog convenience, not the implementation language. Its CLI initializes a session manager with EventStore, then a Tokio ReAct loop prepares context/tool schemas, calls an adapted provider and dispatches tools (`crates/opendev-cli/src/runners.rs:52–75`; agents `react_loop/execution.rs:118–237`). Default native tools include filesystem/search/edit, Bash, memory, notebook file editing, schedule CRUD, questions/network and task/plan operations; model-visible modules not registered here are not counted as exposed features. Custom manifests bind schema to JSON-stdin executables, MCP bridges populate the registry asynchronously, and ToolSearch defers less-used schemas. These are expressive extension primitives with a compiled loop, not arbitrary hot turn programming.

Unlike same-model sample review, SpawnTeammate launches a real independent loop, accepts a different model and optional worktree, and shares file-backed mailboxes/task lists. TeamCreate only registers idle members. Mailbox drain happens automatically only before the child loop; a running child must call CheckMailbox. SendMessage labels every sender `leader`, while CheckMailbox accepts a supplied agent_name and task claims accept claimed_by. Identity is therefore a tool argument/constructor label rather than custody-bound actor identity. Failed worktree creation falls back to shared working directory. The Agent tool's documented resume argument is especially misleading in this snapshot: it reuses a saved session ID, calls manager.spawn with fresh initial messages and saves the new result, without loading previous history (`tools-impl/src/agents/spawn.rs:264–382`; agents `subagents/manager/spawn.rs:212–255`).

Foreground Bash creates a process group and has inner timeout/cancel group cleanup, but the outer dispatcher races cancellation against the whole registry future. Dropping that future can bypass inner cleanup; spawned Tokio child has no kill-on-drop setting. The nonstreaming curl model path and custom executable path similarly lack traced cancellation/group cleanup. Background shell stores initial vector clones while detached readers keep appending elsewhere, so stored output is stale; no native poll/kill verbs occur in Bash's schema. Early read-only-classified tools can launch while provider output is still streaming. The classifier accepts cargo test/check/clippy; arbitrary tests/build scripts and output writes defeat the stronger interpretation of read-only. These are source-inferred custody risks, not executed reproductions.

Compaction masks/prunes/summarizes the current messages in place. CLI records a pre_count before the loop, then slices result.messages at that old offset after it returns (`runtime/query.rs:253–335`): a shorter compacted history permits missed persistence or an out-of-bounds panic. Manual compaction also replaces current session messages. EventStore does retain sequenced normalized message events in primary CLI, but writes are best-effort, event vocabulary is not all provider/action events, and normalized tool output is sanitized before after-middleware. Optional debug logs record pre-adapter payload and ignore append failures. Overflow files themselves clip beyond a maximum. None is a comprehensive original audit, and no model-directed restoration transaction is established.

Skill cache mtime invalidation on next access and asynchronous MCP discovery provide useful change primitives, without the operator's default after-turn/affected-workflow activation boundary. Session resume restores saved data rather than unresolved activity; no refit/outpost handoff exists in the inspected path. Tests assert five mailbox writes by count and shorter compaction/system/summary shape, while the named process-group cleanup test has no post-kill descendant-death assertion. They leave the actor identity, dropped cleanup future, stale background buffers and cross-layer compaction offset faults unchallenged.


## Sweep

The snapshot's README points to a JetBrains successor; this dossier studies the inspectable older GitHub automation, not that new product. The CLI/webhook pipeline retrieves/plans FileChangeRequests, runs bounded modification, validates, commits and creates a regular PR (`handlers/on_ticket.py:519–579,620–668`). A streamable wrapper offers the same Python generator as final-return callable or intermediate suggestion stream. Model actions are XML make_change, create_file and submit_task/submit_result, with no general shell/kernel action in that loop. XML parsing groups matches by known tool name and uses only the first recognized call. Host code can also compile planned replacements into synthetic assistant tool calls, so the message history is partly orchestration output rather than original model behavior.

make_change stages text and compares syntax/linter results against the starting code. Repeated failures are marked SKIPPED and complete; submit_task calculates a no-change error but then overwrites it with SUCCESS and marks a pending task complete. DONE therefore denotes pipeline termination, not a proof that all requested changes worked (`modify_utils.py:897–920,1182–1229`). Retry can escalate MODEL to SLOW_MODEL; five seeded code-review samples may run in separate processes and are collected after pool.join. Neither is live multi-model colleague chat.

When a task completes with a change, both model history and detailed logger history are replaced with the system prompt and current code-state request (`modify.py:173–215`). Optional consumed Mongo stores normalized snapshots using detached writer threads, shared index increment and TTL expiration. Provider streams stop/truncate textual output. This is useful operations visibility, not comprehensive original audit or model-repairable compaction.

API issue/review replacement injects SystemExit into a previous Python thread without waiting for termination; comments instead enter a per-PR queue. Synchronous provider calls and host subprocess validation have no shared cancellation/quiescence contract. The focused matching test has specific expected placements/scores/no-match assertions, while no inspected assertion attacks false completion, compacted-history repair or stopped worker custody. The useful Arconaut lessons are staged streamable workflow, baseline feedback and explicit task outcomes; the unsafe transfers would be claiming model live collaboration, original audit or refit continuity.


## Kimi CLI

KimiSoul drives an asyncio step/continuation loop with in-repository Kosong and KAOS machinery. Kosong dispatches complete tool calls during provider generation, cancels and awaits tracked futures when generation fails/cancels, and exposes normalized streamed parts/results to the wire. The concrete Kimi adapter converts history/schema and calls async OpenAI SDK. Soul waits results, grows context and continues until no tools/rejection/repetition; steer messages enter between steps and before stopping. The run wrapper cancels and awaits soul rather than injecting a Python thread exception.

Native Shell has fresh foreground execution or task-backed background mode; TaskList/TaskOutput/TaskStop expose stable task identity, status, full output file hints and bounded blocking reads. Foreground KAOS kills only the direct child and does not reap in kill; no process group is created, and deadline wraps pipe reading before a later process.wait. A shell that closes its output before continuing can therefore escape that deadline. Background Bash is stronger: detached worker, group identity, persisted control/heartbeat, file stdout/stderr, TERM/KILL grace and process wait. Background agents are instead current-process asyncio tasks; marking them killed precedes awaited cleanup. Reload preserves background work and is not a refit-quiescence boundary.

Agent genuinely restores saved child context/system prompt and maintains agent identity. A saved model or explicit override clones the child LLM, and active resume is rejected; the launch state is marked before background dispatch. This contrasts directly with OpenDev's ID-only resume. Parent can inspect results, but native actions do not send a message to a still-running colleague; TaskOutput plus later idle resume is limited collaboration, not an IRC-style peer bus.

FlowRunner executes task/decision prompt graphs with labelled edges, using the same soul/history and model <choice> output. This is actual workflow programming, alongside native tool imports/hooks/MCP. It is still prompt-stage orchestration around a host-defined turn, not model hot installation of a new core loop. Invalid choices retry within one node before the outer valid-move counter advances, a boundary worth testing under persistently malformed choice output.

Compaction supports custom focus and retained user-turn tail, emits wire lifecycle events, rotates the old normalized context file, writes summary/checkpoints and reinjects an active-task snapshot. Checkpoint/D-Mail reversion also preserves the prior file; D-Mail is optional and disabled by default. Those are useful repair primitives, while filesystem effects remain after rewind. Merged complete wire messages append to protocol-versioned JSONL with wall timestamps; recorder failure logs rather than failing the turn. Foreground output builder clips before the wire. Neither original HTTP payload/chunk order nor full process bytes are guaranteed by this capture. Operator /feedback submits text plus session/version/OS/model, not a model rageshake or captured-state bead.

Inspected resume tests mock soul while exercising real context/store/runner and assert accumulated assistant messages, same identity and active-instance guard. Worker stop tests execute a sleep process and assert persisted killed/timeout reason; they do not independently probe descendants. Compaction tests assert focus/tail structure without semantic preservation. The useful Arconaut leads are strong ongoing-work handles, real data resume, workflow graphs and rotated contexts; background-versus-foreground custody, in-process agents, original audit and refit remain separate questions.


## Mistral Vibe

This snapshot contains a default Python AgentLoop and an experimental unified Rust harness with substantial public source and Python host adapters. CLI selects legacy by default unless explicit/rollout selection chooses unified. A LocalHarness uses app-server protocols over an in-process transport; a host refuses mixed backends. Capabilities below distinguish those branches rather than infer core language from packaged binaries.

The Python loop runs before-turn middleware, projected provider calls, resolved tool batches, result messages and continuation/pending injections. It saves after each successful model step and in finally. Mistral's concrete adapter awaits SDK stream_async and closes the stream with async-with. Concurrent tool cancellation cancels and gathers children, while GeneratorExit only issues cancellation before monitor cleanup. Native typed filesystem/Bash/skill/todo/question/plan/network tools are discovered from builtin/user/project paths with variant availability/priority/profile filtering. Python modules are cached in sys.modules, so discovering them again does not guarantee reloading edited source.

Legacy Bash creates a fresh shell or consumes terminal IO and finally force-kills/waits through the shared helper. Managed Bash is a different selectable variant: a terminal process with stable ID, manifest, log reader, output cursor, stdin/text/control/raw bytes and list/inspect/kill/reset. A soft foreground deadline hands back a live background handle; hard timeout kills. Logs are also writable/appended through model operations, which excludes treating them as immutable audit. Task creates a real child loop/session/lease under selected agent profile, shares permission store, persists the link, waits for child progress/result and on cancellation interrupts then awaits the child. This is concrete concurrent child execution, not a provider-choice claim.

Compaction works on a snapshot, appends a summary/context boundary and preserves older normalized messages. Model input selects from the latest boundary plus system messages; this is a useful effective-context projection. SessionLogger records nonsystem normalized messages, appending when a fingerprint boundary matches and otherwise rewriting the current JSONL through temp/fsync/replace. Inplace rewind permanently truncates old turns, whereas fork preserves the old saved session; selected file snapshots can restore disk edits. Provider wire/chunk order and preclip output are not all captured, so original audit remains limited despite retaining precompaction chat.

Reload prepares new managers/prompts/backend off-loop with a generation guard, then swaps synchronously. Active turns can receive the committed objects; the previous provider pool is closed only after the active turn ends, to protect current stream/child sampling. This prevents partial/stale updates but does not implement the operator's default whole-turn/affected-workflow activation, nor a executable refit handshake. Teleport checks remote Git branch/commit, asks before needed push and starts a hosted workflow with selected/summary context, returning a URL; it is useful context portability, not replacement of the running main executable.

The unified Rust Engine accepts sequenced commands, emits action/observation transitions and checkpoints, and restores with an explicit input cursor. Python model/tool handlers supply external effects and apply action-ID results. The simple reference driver schedules emitted directives with asyncio tasks; native state ownership alone does not prove their cancellation/quiescence. Native run_typescript dispatches into an embedded V8 evaluation/replay engine, with pending tool operations/IDs, pre/post hooks, effect/operation bounds, heap termination and a watchdog. This is actual model-programmable orchestration, not Node ambient OS execution or a standing Python kernel. Bare host defaults enable bounded programmatic calls but disable background/subagent/compaction features; configured application hosts can enable them. The configured child controller's send operation uses persisted intent/admission/acknowledgment receipts and can steer a running child or start an idle turn. That is a promising model collaboration mechanism, within parent-child scope, whose complete host recovery/custody deserves a dedicated follow-up audit.

Tests independently challenge append-boundary preservation, mock hook rebinds and pure native pending-compaction restore/projection equality. Programmatic tool tests compare live/restored checkpoints while excluding private/intermediary material from model projection. These are useful source oracles; their state equality must not be promoted to external effect exactly-once behavior or comprehensive original audit. No reference programs were run.


## Mechanisms across the cohort

The ten references expose different action grammars, and that choice constrains model ergonomics more than the language label does. Mini-SWE-agent makes the operating system the model's one executable action. SWE-agent adds installed command bundles and a persistent shell service. GPT Engineer and Devika impose named generation/research stages. Sweep makes staged code replacement its central action. Trae and OpenDev use richer schema catalogs and host dispatch. DeepAgents composes middleware graphs and backend actions. Kimi offers both ordinary tools and prompt-flow graphs. Mistral's configured unified branch adds a model-authored executable orchestration program. The [operator-interface cohort](python-operator-interfaces.md) studies three further ways to make programming conversation and execution direct; the [hosted/workspace cohort](hosted-workspace-agents.md) examines externally scheduled work and durable framework state.

| Trae | JSON tools, MCP bridge and execution model | Long-lived Bash process/private output buffers | Subshell commands discard cd/env; completion can skip coissued actions; local parallel invocation race |
| DeepAgents | Middleware/graph programs, backend files/execute, hosted task tools | Supplied Store/checkpoint plus stable remote thread/task/run | Runtime scheduler external; remote cancel acceptance is not observed termination |
| OpenDev | Rust ReAct/schema deferral/custom executable tools/teammates | Background IDs, child metadata, file inbox/team/task state | Stale background output, outer-drop cleanup gap, ID-only child resume and compaction offset fault |
| Sweep | XML replacement tools and streamable plan/edit/publish stages | Staged files, GitHub issue/PR, optional expiring Mongo | False-complete/skip semantics, lost prior context detail and async exception injection |
| Kimi CLI | In-repo tools/scheduler, FlowRunner graph, child model aliases | Actual restored child ID/history; explicit task output/control | Foreground child-only cleanup; agents still parent asyncio tasks; no live child message action |
| Mistral Vibe | Python middleware/tool variants; configured Rust run_typescript | Managed terminal cursors, child sessions and native action/input receipts | Two branches have different availability; normalized logs mutable; state replay does not prove effect custody |

Compaction gives a particularly discriminating comparison. Sweep replaces both model and detailed history with current code state. OpenDev mutates messages in place, then a separate persistence layer incorrectly relies on the old length. Kimi rotates the previous normalized context file before rewriting the effective view. DeepAgents and Mistral append effective-context boundaries/events while retaining previous message state. Those latter mechanisms better support repair research, but their retention still begins after some clipping, normalization or offloading. No cohort member earns comprehensive original-audit credit merely by saving a trajectory, appending a message or exposing a database.

Likewise, command completion, tool observer completion and owned resource settlement must be separate. Mini/GPTE/Devika synchronous process patterns have different timeout weaknesses; Trae's process survives tool deadline until a later restart; OpenDev outer cancellation can bypass inner group cleanup; Kimi foreground and background modes have different kill/reap contracts. Mistral's managed shell explicitly transfers ownership into a returned handle on soft timeout, and DeepAgents makes remote work identity inspectable. These furnish concrete designs for experiments without supplying Arconaut's refit barrier by inference.

Model choice also takes several forms: sequential retry escalation, same-model sampling/voting, per-child alias selection, genuinely simultaneous colleague loops and remote tasks. Only the running-child/task messaging paths should carry collaboration credit. OpenDev has mailbox primitives but weak actor labels and no automatic decision-loop drain. DeepAgents remote updates use same-thread interrupted follow-up. Kimi rejects active resume and offers output inspection, so it needs an additional live-message protocol. Mistral's configured unified controller stores operation receipts and child-generation admission before acknowledging send. None by itself establishes a general authenticated peer room.

The first Arconaut milestone should therefore distinguish a minimal agent capable of building its own source from the harder continuity claims. A native file/process interface and strong model programming surface can make build-in-Arconaut useful early. Original evidence capture, context projection/repair, resource custody and pending-change activation should be designed as separate explicit contracts from that beginning. The cohort supplies candidate mechanisms and counterexamples, not a dependency selection or permission to port legacy code.
