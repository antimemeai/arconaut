## mcp-agent-mail

This Python HTTP MCP service is an external coordination fabric, not an agent loop. `register_agent` records external program/model metadata and a durable identity/token; `_authenticate_agent` permits a previously bound session or constant-time token verification with explicit legacy/window exceptions (`app.py:5231–5306,5988–6028`). `macro_start_session` composes registration, optional reservation and inbox through the actual tool registry (`10002–10087`). HTTP bearer/JWT admission is separate (`http.py:668–722`).

`send_message` has real native addresses, threads/topics, per-recipient records and delivery IDs (`app.py:7132–7240`). A blocked automatic contact request **does not queue the body**; sender must send again. Stored delivery neither checks busy model state nor forces context injection. Debounced signal files are overwritten hints with best-effort errors; polling clears the hint without marking messages read (`storage.py:3618–3683`, `app.py:9584–9696`). Explicit `acknowledge_message` preserves per-recipient receipt timestamps; it is not execution completion (`9913–9995`).

Canonical/outbox copies and private BCC-redacted inboxes are written before an awaited Git commit (`storage.py:1551–1688,169–213`). The DB message commits first; archive errors attempt compensating DB deletion (`app.py:5585–5730`). Body stripping and image conversion mean this is **not exact original-input audit**; partial files/crashes and failed compensation remain separate fault classes. The compensating test deliberately raises at the entire bundle call, then queries actual row counts (`test_messaging_semantics.py:1209–1252`); it does not test partial file publication or crash durability. The repeated read/ack test checks literal unchanged timestamps, a useful narrow oracle (`test_message_delivery_regression.py:825–872`).

Persistent mail search has real sender/recipient filtering in both FTS5 and parameterized LIKE fallback (`app.py:10621–10836`); this is an app database, not generic model SQL. On-demand thread refinement sees compact derived summaries and leaves stored mail intact (`10950–11038`). File reservations still grant overlapping exclusive intent while reporting conflicts; code enforcement is explicitly advisory and external precommit guard scope is distinct (`11620–11749`). Short TTL actually warns despite a stronger docstring assertion (`11440–11524`). Settings cache reset is an explicit next-access primitive (`config.py:607–632`), not whole-agent refit. All23 cells preserve that service role; no downloaded program/test ran.


## ntm

NTM's compiled Go machinery orchestrates separate coding-agent TUIs through tmux/SSH. The shared human/robot dispatch service resolves explicit target selectors/type/variant, builds/redacts final prompts and emits per-pane protocol receipts (`dispatch/dispatch.go:1–197`). It refuses positive dead-shell/trust frames before typing, then clears/stages/submits with provider-specific choreography (`373–439`). Unknown layouts/capture failures can proceed best effort; OpenCode's positively empty composer refusal is stronger than disappearance alone (`tmux/opencode_submit.go:132–192`). Interrupt is a terminal key, Escape for OMP and Ctrl+C elsewhere, not a settled provider cancellation (`tmux/session.go:3254–3296`).

The executable workflow/pipeline is a distinct programmable outer runtime. The critical agent-send record is written **before paste** and binds definition hash, tmux endpoint, session, physical pane/PID and prompt hash (`pipeline/executor.go:1738–1847`). `sending` means uncertain outcome: ordinary resume and automatic retry will not submit again (`987–1007`). Completed records/foreach fingerprints/rounds retain already settled work (`state_resume.go:13–95`); response evidence is bounded scrollback, and WaitNone fulfills submission only (`executor.go:1845–1916`). Detached resume keeps runID but creates a new request token and acquires child run ownership before reading state (`background_resume.go:1–105`). The mock test explicitly asserts one original paste, no ordinary-resume paste, and one intentional restart paste (`submission_verification_test.go:277–308`). This is useful uncertainty handling, not a general transaction over shell/model side effects.

Command steps really launch `/bin/sh -c`, not a hypothetical plugin (`executor.go:1305–1400`). Linux waits use WNOWAIT to pin leader identity across descendants, TERM/grace/KILL/settlement and reaping (`process_wait_linux.go:16–128`). The gated child test only enables its harmful late effect **after cleanup returns**, then fails if it appears (`process_group_lifecycle_linux_test.go:61–98`), a strong causal oracle read without execution. Escaped groups and other platforms remain distinct boundaries; this control plane owns its command groups rather than shared external service lifetimes.

Native compaction validates the exact original process, server-wide provider transcript attribution, fresh usage/model/path and two stable ready observations; remote/local accounting mismatch and ambiguity refuse (`context/rotation.go:1684–1872`). The eight-mode test attacks stale/same/wrong transcript, changed identity, cancellation, missing baseline and busy completion with literal150000→30000 accounting (`rotation_test.go:75–160`). Rotation instead gets a completed generated summary, launches replacement and submits handoff before predecessor retirement; failed handoff preserves original (`rotation.go:1505–1615`). This is implemented external-agent replacement continuity, not recompiling/reinhabiting NTM with unresolved execution intact.

Audit provides writer-local hash/sequence JSONL with fsync on flush, but ordinary Log may only buffer; payloads and prompt history are redacted and privacy may omit them (`audit/logger.go:145–193,513–580`, `session/prompts.go:100–132,180–238`). No affected-workflow/end-turn timing barrier follows. SSH actuates external tmux (`tmux/client.go:279–301`); Agent Mail remains a consumed service, with mail prepared-handle subject/consumption rules separate from terminal targeting (`cli/mail.go:100–146`). ## station

It differs from Arconaut's desired shared-fabric consumer role. ## Comparative findings and completion

All three pinned references are complete: 69 capability cells, 28 native operation families, 92 exact local evidence ranges and 15 inspected test files. The owned stdlib validation in `context/coordination-matrix/validation.json` verifies row identity, all 23 registry axes, local reference ownership, real files/ranges, evidence references and read-only test declarations. It does not execute or certify upstream behavior. Rows [mcp-agent-mail](../rows/mcp-agent-mail.json), [ntm](../rows/ntm.json) and [station](../rows/station.json) retain the full source/test boundaries.

The unit supplies three different ownership patterns. Agent Mail is an external service that stores and searches addressed communication without governing agent programs. NTM is a compiled control plane that targets external agents through tmux and owns workflow command groups. Station owns a scientific ecosystem, including its agents, storage and evaluation/coder workers. Arconaut can study the concrete primitives while preserving the operator's separate fabric ownership: consuming a mailbox, kernel or evaluation service need not imply becoming its governor.

Communication needs more than one success state. Agent Mail separates stored message, inbox retrieval, explicit read and explicit acknowledgement; a filesystem signal is a hint and a reservation is advisory intent. NTM can establish preconditions before terminal actuation and records a pipeline's unknown SENDING outcome so ordinary recovery will not silently resend it. Station's notification merge protects concurrent arrivals, but notification delivery itself marks an item read. None of these states proves the model understood the message or the requested physical work completed. An Arconaut collaboration design should represent stored, offered, incorporated and acted-on states with operation identity, rather than collapse them into one delivery flag.

Unknown outcomes require particular care. NTM's refuse-to-resend rule and Linux causal child-cleanup test are useful concrete fault-class evidence. Station's fast-lane timeout leaves work queued or active; its later recovery rolls back selected provisional artifacts and may delete uncommitted model history. Agent Mail's DB/Git path compensates an archive failure but does not prove atomic durability after every partial filesystem crash. Refit therefore needs an explicit settlement contract for owned provider/program activity and an explicit pause contract for standing work; a signal, queue timeout, prompt receipt, cleared handle map or reconstructed transcript is insufficient by itself.

Audit and active context should have separate lifetimes. Agent Mail stores processed canonical message artifacts with per-recipient visibility. NTM has privacy/redaction, bounded outputs and writer-local hash chains, and some query paths skip malformed records. Station records decoded/provider metadata projections, swallows some append failures, expires tick snapshots and deliberately rewrites away uncommitted history during recovery. Its pending-versus-anchored compaction event is useful for studying context transformations, while that recovery is a direct counterexample to an original audit that captures everything. Arconaut's effective-context repair should change the working projection while preserving captured originals and the repair event.

Change timing is also heterogeneous. NTM's watched dashboard config has a debounce and retained-prior-config failure behavior; Station's runtime API generation is consulted before a new provider request, context anchors are rebuilt before later sends, and general constants require restart. Agent Mail's settings cache reset only affects later settings retrieval. None establishes the operator's universal default of activation after the current turn or affected workflow, nor a compile/outpost/refit handoff with owned work quiesced. Partial external-agent rotation in NTM belongs to a different executable and work boundary.

Finally, an oracle must match the claim. NTM's process test gates a harmful late effect until after cleanup returns; this is stronger than asserting that a kill method was called. Its nominal concurrent-audit-writers test instantiates one logger and proves only that chain. Station's tests establish merge, anchor, provisional tombstone, verdict-file and repair transitions; its auditor model's agreement is not scientific truth, and scientific code refinement is not implemented harness autodroit. A nonblocking `suggest` is closer to the desired complaint affordance than `request_human`, but neither captures a complete state bundle in a standing complaint database. These differences define research questions; they select no dependency, architecture or implementation for Arconaut.
