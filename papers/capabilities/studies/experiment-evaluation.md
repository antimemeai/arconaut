# Experiment and evaluation mechanisms

These five references study changing programs against observations. They are not
five interchangeable complete coding agents. Their linked rows preserve exact
revision, action surfaces, selection authority, inspected tests and uncertainty.
No model, GPU run, environment server or reference test suite was executed here.

Autoresearch separates one editable training file from fixed preparation/evaluation
code and gives an external coding agent an explicit baseline/edit/run/keep/discard
protocol. This is useful for understandable autonomous experimentation. The agent
engine, command cancellation and continual execution are instructions to another
harness. The printed metric is not a harness correctness oracle, and the fixed
evaluator still calls an editable model's loss implementation. It must not be
mistaken for protection against score manipulation. Run logs/TSV/commits are useful
records, narrower than complete original IO retention.

Self-Harness supplies executable candidate queues, bounded virtual-hook surfaces,
materialization, separate evaluations and promotion to child branch records. Hooks
include prompts, tools, subagents, middleware, permissions and runtime policy, so
this is broader than prompt editing. Acceptance requires no mean pass-rate drop on
any selected split and an improvement on at least one; defaults use train/heldout
and two repeats. It validates repeat counts and denominators, not task identity or
statistical confidence. Promotion is not live executable activation. Harbor timeout
returns a result after an await timeout, without this source proving the remote
process has terminated.

GEPA makes evaluator, reflection/proposer, acceptance, selection, checkpoint and
budget owners distinct. Its current generic optimization surface can operate on
code and multi-component programs, not merely prompts. A significant governance
point is explicit in source: selection strategy is authoritative and custom selection
may surface proposals rejected by the acceptance criterion. A strict criterion alone
therefore cannot stand for an inviolable machine invariant. Rejection callbacks
preserve the difference between score regression and an unselected passing proposal.
Optional held-out test scoring stays outside optimization server/budget input. The
evaluator itself remains user supplied. Eval-call budget and proposer dollar budget
are different quantities with different owners; a saved candidate state or resumed
external Claude session is not native harness refit continuity.

Aviary supplies typed actions, schema discovery, call/result identity, ordered batch
responses and explicit concurrency safety. Within a batch, unsafe tools take a
writer lock while safe tools may overlap. The lock is created per exec_tool_calls,
so cross-batch exclusion needs an owning policy. Sync tools run in threads; timeout
of the await cannot stand for termination of that thread/external effect. Its tests
use an actual counter to distinguish overlap/exclusion, while timeout tests primarily
assert TimeoutError. This is a good example of asking what a test observes rather
than crediting its name. Frames may contain a subset of state; they are not universal
original audit.

LDP's explicit get_asv/next-state/environment step and operation graph make alternative
agent policies experimentally composable. Transition records separate before/after
state, observations, actions, rewards and timing. The active window can hide prior
material while prior states remain separately available if a caller retains them.
APE uses reward/gradient examples to propose a prompt and checks template-variable
compatibility before mutation. That gate is not independent performance validation.
Call-keyed graph context is clearable and excluded from ordinary model serialization;
comments about a DB backend do not establish an implemented standing database.
HTTP agent state handoff likewise does not preserve live graph contexts or native
process work by itself.

For autodroit, the transferable structure is an explicit experiment whose candidate,
external effects, observed evidence, selection decision and activation are separate
objects. The model can govern research choices and explore novel strategies while
correctness claims remain bounded by direct independent oracles. Selecting an improved
candidate, activating a program after a settled turn, and refitting a compiled core
are three different operations to specify.
