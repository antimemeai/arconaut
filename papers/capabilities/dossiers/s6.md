# s6

Stop/continue, readiness, independent logging and file-descriptor custody clarify what an outpost/refit must coordinate versus delegate to OS services.

Role: OS service supervision and descriptor custody tools. Runtime: C.

Pinned source: [https://github.com/skarnet/s6](https://github.com/skarnet/s6); revision/version `67254f0c147f9b9f71aabc7988e52bdaeb9576ab`.

Small independent Unix processes communicate through service-directory controls, event FIFOs and Unix sockets.

Operator/OS daemon supervisor, outside the refitting agent; shared services should not be paused by their consumer.

Inspection: Read supervisor signal/state dispatch, readiness, control CLI, fd-holder and log contracts, and available test runner.

Limits of this study: No populated src/tests suite in snapshot and no daemon executed; downstream service protocols and complete logger implementation not audited.

## Actions

### s6-svc

Surface: supplied primitive.

Input: Service dirs plus stop/continue/restart/reload/wait flags

Result: Control delivery exit code or event-wait result

Lifecycle: Control and readiness are distinct; non-listening supervisor reports error.

Authority: OS service-dir access

Evidence: [control](#evidence-control), [signal](#evidence-signal).

### s6-fdholder store/retrieve/list/getdump/setdump

Surface: supplied primitive.

Input: FD, identity, expiration and transfer operation

Result: Descriptor or custody dump/result

Lifecycle: Independent daemon survives client replacement; its death loses held FDs absent transfer.

Authority: Unix socket access rules

Evidence: [fd](#evidence-fd).

### s6-log

Surface: supplied primitive.

Input: Input stream and logging script/flush/line options

Result: Processed/rotated log lines

Lifecycle: Independent logger; line processing changes framing by configured defaults.

Authority: OS process/pipe authority

Evidence: [log](#evidence-log).

## Useful mechanisms

- Standing services and descriptor custody can remain independent of a harness rebuild.
- Readiness, paused state and restart are distinct observable operations.

## Material limits

- STOP targets process/group; it does not settle in-flight provider requests or serialize application work.
- A consumer refit must not stop shared service daemons; the FD holder itself needs separate continuity.

## Arconaut design questions

- Which resources belong to the agent/outpost, and which belong to independently supervised services?
- What exact settled/paused state must be checked before refit rather than inferred from supervisor acknowledgement?
