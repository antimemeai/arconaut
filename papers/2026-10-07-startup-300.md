## What the clock means

Parent monotonic time begins before spawning scripts/blackbird, including launcher,
process/dynamic loading, native journal replay/recovery, session/context/engine,
transcript/UI setup and first frame emission into a110x35 PTY. Ghostty environment
selects the actual supplied image path. The consumer drains all terminal bytes and
requires the composer label plus synchronized-frame end. This measures emitted
frames, not Ghostty GPU presentation or input-to-photon latency.

After the first frame, send a split-marker Lua command that calls the native
workflow_registry tool through audited operation admission/settlement and asserts
ultracode discovery. The input never contains the complete success marker; observing
it in output requires the call to succeed. This second endpoint includes input
handling and frame delivery. It is NOT provider-request serialization/admission
readiness; the local tool was chosen to avoid inference/auth/network costs.
Every process exits0. No failed/outlying run discarded and no hidden retries.
P90 is nearest rank: sorted observation90 of100. Full p50/p90/p95/p99/max retained.

Each start receives a new private APFS clone of its same seed; cloning is outside
the clock. The clone's startup writes cannot change subsequent prefixes. Copies
are removed only after their process exits. Ordinary OS cache; no cache flush,
forced cold-cache claim or cumulative session growth. Fresh means new process
(and empty session in the fresh case), not cold machine or instruction cache.

## Interpretation and limits

Host contention was substantial: one-minute load11.33 at start and50.01 mid-run
on16 logical CPUs. These are observed loaded-machine results, not an idle baseline.
No claim attributes any individual tail delay to scheduling versus storage/core
work: native phase/CPU/read-byte attribution was not enabled in the normal build.
Heavy median797.634ms and p901468.383ms are far from the under100ms goal. The empty
case median65.623ms meets100ms, but its p90140.133ms does not. Even with explicit
load qualification, these data do not establish the requested startup target.

## Reproduce

Use a new output directory each time; the script refuses existing run/sample
artifacts. Both sources are owned development utilities; fixture target is
EXCLUDE_FROM_ALL, with no added production instrumentation or Python runtime.

```sh
cmake --build build/release --target startup_scenarios -j2
mkdir -p context/my-startup-study
build/release/startup_scenarios heavy context/my-startup-study/heavy-seed
build/release/startup_scenarios weird context/my-startup-study/weird-seed
scripts/benchmark-startup context/my-startup-study --count 100
```

The fixture generator uses existing native RetainedState/ContextStore/SessionStore
and terminal-state encoding. No foreign source was executed or adopted. Initial
fixture-directory permission refusal was corrected before the pilot and recorded
in JOURNAL; no production defect/optimization was introduced by this study.
