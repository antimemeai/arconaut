# Arconaut development and research campaign

2026-10-06. Proposal for discussion. Build Arco into the operator's programmable
software workshop, then use that workshop to improve itself under sustained real
work. The finish line is a useful continuing session with editable workflows,
independent colleagues, consumed computation, recoverable context and attributable
experiments. The current managed-compaction campaign supplies the first mechanism.

## What the notes imply

The [operator brief](../docs/FOUNDATION.md) calls for unusual composition, substantial
normal model agency and autodroit governed by the model with operator steering.
The [behavioral scenarios](../docs/BEHAVIOR.md) make ordinary coding, live rooms,
turn redefinition, context repair, refit, messy-run audit and measured improvement
one connected product. The campaign should exercise that combination while each
wave leaves Arco more useful for the next.

The [capability synthesis](capabilities/SYNTHESIS.md) distinguishes programmable
execution, peer messaging, service clients, original-preserving context and
experimental promotion. A roster, tool registration, remembered state or a positive
score cannot substitute for the corresponding executed behavior. RRC now supplies
compiled self-development, so full native hot reload need not precede a powerful
programmable workshop. The current bootstrap-first sequencing in
[IMPLEMENTATION_PLAN](../docs/IMPLEMENTATION_PLAN.md) remains in force.

## Wave one Sustained work and repair

After B1 completes, make hours of actual work comfortable and diagnosable.

- Add configurable context-management programs, explicit trigger/target units and
  bounded inspection of revisions, summaries and originals. Model/operator can
  revise the policy; repair can grow context. Default managed publication remains
  at turn conclusion. No guessed model limit or silent mandatory summarization.
- Resolve the bounded coding-loop failures that currently strand function-call
  linkage after arbitrary Lua errors. Expose unfinished file/process outcomes and
  explicit reconciliation without automatically rerunning uncertain effects.
- Add a usable audit query surface and measure actual replay/request assembly on
  long histories. Complete the journal continuation/emergency-control paths that
  the measured workload needs before an audit-capacity limit ends normal work.
  This is a concrete integration need, not a return to finishing every U1 subplan
  before shipping features.
- Introduce local rageshake with a complaint bead and captured context, program,
  operation and audit references. Reporting lets the model continue ordinary work;
  external-table delivery follows selection of the consuming interface in wave four.

Exit exercise: a sustained coding session crosses repeated compactions and native
RRC, receives steering, encounters a genuine tool/workflow failure, repairs the
context and continues. A separate inspection locates exact inputs/results and the
complaint. Record lost work, unknown effects and unsupported recovery honestly.

## Wave two Tools and turns as ordinary programs

Make Lua the expressive action language shared by operator and model.

- Implement dynamic tool definitions: schemas, source, discovery, version and
  execution through the existing effect/audit boundary.
- Add audited modules and configuration with candidate validation, effective-source
  inspection and activation after affected turns/workflows conclude. A failed
  candidate leaves the working generation usable.
- Add reusable workflow composition for branching, joins, external waits, bounded
  retries and cancellation. Independent control must remain responsive while
  work waits. Decide retry from the actual effect class and observed outcome.
- Expose pending versus effective configuration and interrupt-and-apply-now to
  both operator and model. Include small skill metadata/on-demand loading when
  it directly helps tool and program discovery.

Exit exercise: while doing real repository work, the model defines a useful tool,
uses it, revises its implementation and replaces the serial turn with a workflow
that obtains an independent review. Observe the old workflow finishing under its
old definition and the next one using the new definition; then exercise explicit
interruption/application and a failed load. This makes programmability real.

## Wave three Colleagues and remote work

The colleague roster is Kimi, MiMo, another ChatGPT session, Claude, or Grok. Each
colleague has an independent context; configured connection/authentication must be
confirmed before use. Use independent participants, rather than forcing all
collaboration into a parent/child request tree.

- Integrate Kimi's existing subscription CLI as an addressable colleague with
  captured sessions, exact resume and explicit running/completed/failed status.
  Native provider adaptation and a CLI colleague remain distinct mechanisms.
- Implement a minimal room and direct mail: sender/message/recipient identity,
  durable acceptance, inclusion in a later request and correlated replies.
  Busy-target delivery and idle continuation must work. Arrival during a stream
  does not imply that the already-dispatched request read the new message.
- Add selected-context branches and a remote outpost working on Neuroses through
  a clear SSH host/path interface. Incorporate findings with source attribution
  and explicit conflict handling. Isolated working directories are the default
  for concurrent code edits; shared-workspace experiments remain possible.

Exit exercise: operator, OpenAI participant and Kimi colleague work on one task;
a remote peer investigates independently. Send a priority change to a busy peer,
compact one participant, reconnect another and integrate conflicting conclusions.
Check actual messages in subsequent requests and real resulting artifacts, rather
than relying on final reports. Other peers keep their own context lineages.

## Wave four Shared computation and study data

Connect Arco to computation and records whose lifetime belongs outside Arco.

- Consume one selected standing database and one selected computation service
  through versioned client/workload references. Demonstrate useful queries and
  continuing state, including another consumer. Select the actual service/API
  with the operator before adopting or configuring it; do not build a fabric
  control plane inside Arco.
- Deliver complaint records to the selected external table, with offline capture,
  per-sink pending/failed/unknown status and delivery reconciliation. Link recorded
  experiments and failures to the original audit instead of inventing another
  authoritative event store.

Exit exercise: two Arcos consume the same service. Compact and RRC one; the other
continues useful computation. Reconnect the first and inspect actual workload
state. A complaint remains actionable after its reporter has moved on.

## Wave five Model governed improvement experiments

Build the actual autodroit loop from evidence produced by the earlier waves.

- Give model/operator editable objectives, trial budgets, candidate surfaces,
  experiment programs and keep/revise/reverse decisions. Support pause/resume
  and live steering without approval on each command.
- Retain hypothesis, baseline, effective candidate source/configuration, exact
  task/evaluator versions, outcomes, resource use and activation/reversal.
  Failed trials stay available. Evaluator changes create a separately identified
  experimental treatment; they do not silently improve the previous score.
- Optimize demonstrated bottlenecks: context selection and repair, discovery and
  tool-result ergonomics, review scheduling, replay/request assembly, or workflow
  failure recovery. Choose from actual observed failures rather than generic
  prompt polishing. Implement the successful candidate in Arco and keep using it.

The [autodroit research](2026-09-30-autodroit-frumentarii.md),
[experiment survey](capabilities/studies/experiment-evaluation.md) and
[CLM study](2026-10-01-context-language-models-study.md) motivate separating diagnosis,
selection, final evaluation and activation. The model may govern the research;
independent expected outcomes still distinguish an improvement from an attractive
score. A development split and a repeatedly screened validation split are not a
fresh final evaluation. Reserve unseen tasks or fault schedules for that purpose.

Start with three concrete hypotheses and at most two candidate strategies per
hypothesis, excluding the baseline. Suggested hypotheses: structured selection
preserves coding constraints better than generic summary; output retrieval reduces
request growth without losing diagnostic facts; a colleague consulted at failure
boundaries repairs genuine defects more efficiently than repeated self-review.
These are hypotheses, not claims the campaign should manufacture support for.

Use matched task families and report correctness, repair success, steering latency,
wall time, provider calls, available usage/cache facts and audit growth separately.
Keep raw repetitions and compare variability. Never score missing work as efficiency
or claim savings from bytes alone. Choose repetitions from the effect size and
observed variation; the first pilot is for measurement design, not a significance
claim. Jev can help rank diagnosis/retrieval leads, with recorded judgments and a
native-selection control; it is neither an oracle nor a promotion gate.

Exit exercise: the model diagnoses a retained failure, proposes a change, compares
it with baseline, rejects at least an actually inferior trial if encountered,
activates a justified candidate through Lua or RRC, and demonstrates reversal of
its effective behavior. Ordinary code work continues across the experiment.

## Wave six Deeper replacement and custody

Once the workshop is useful, extend the runtime boundary where it buys continuity.

First implement an explicit prior-image fallback after failed startup, avoiding a
restart storm and automatic replay of uncertain requests. Then implement a narrow
native component ABI with source/artifact identity, validation, generation pins,
state migration and retirement. Full outpost refit follows where foundation changes
or preserved standing programs demand it. RCC++/cr/Godot-related code remains a
mechanism reference until a concrete adoption is discussed.

The [native-reload](2026-10-01-native-reload-grounding.md) and
[custody studies](2026-10-01-refit-custody-grounding.md) identify the real obligations:
no old callbacks/destructors executing after unload; no active main programs or
provider requests at refit; actual same standing worker preserved alive and paused;
consumed shared services untouched. RRC restores a conversation in a new process,
which is already useful but does not establish any of those stronger guarantees.

Exit exercise: failed compile, failed startup, delayed old callback, outpost loss
and unsuccessful return have explicit outcomes. A preserved worker's externally
observed state continues after return; an independent shared-service consumer
progresses throughout. A stuck pause blocks refit visibly.

## The integrated campaign

The coding workload produces useful software. Its first three assignments are
an audit explorer with bounded original/request/context inspection; local rageshake
with bead creation and captured state; and a Lua tool registry with source/schema
inspection and tested activation. These deliverables become the workshop's working
tools. Subsequent assignments build the remaining waves rather than spending the
campaign exclusively solving disposable benchmark repositories.

While implementing those assignments, Arco experiments with its context policy,
tool-output presentation and review strategy. Keep the product deliverable and
harness intervention separately attributable: a feature passing its behavioral
oracle is the work outcome; comparable runs determine whether the harness change
helped produce it. Do not repeatedly solve the identical completed feature and
call remembered solutions independent trials. Use matched task variants and reserve
fresh controlled cases for final evaluation. Deterministic fault fixtures supplement
real productive work; they do not replace it.

Use twelve task scenarios drawn from the seven behavioral scenarios: six
repository tasks, two evidence/research tasks, two coordination tasks and two
self-improvement tasks. Pilot three first. Each has predeclared behavioral outcomes
and inputs, not a broad completion score. Fixtures support deterministic failures;
live runs establish practical workflow use. Real Arco features developed during
the campaign supply the work, with controlled repositories for independent final
evaluation. No neighboring project is enlisted without an explicit assignment.

A representative session receives a real coding assignment with a constraint
buried in earlier context; uses a model-authored tool and changed turn; asks a
busy colleague a question; obtains remote evidence; consumes standing state;
compacts, discovers an omission and repairs it; encounters a failed native build;
returns through RRC; files a complaint; then changes and evaluates its own workflow.
The final artifact must meet the original constraint, and independent inspection
must explain what each participant saw and caused. Run stronger refit/worker parts
only after their owning wave exists.

Independent Kimi reviews target consequential code boundaries and campaign oracles,
not every edit. Relevant diagnostics/sanitizers and direct failure oracles remain
part of each conceptual unit; portable checks run on Neuroses at coherent source
snapshots. Mutations remain deferred under current operator steering and would run
only on the fleet when separately reauthorized. More parallel coding needs separate
working directories and a clear owner for each whole unit.

## Blackbird execution cycle

Each conceptual unit starts by obtaining and reading relevant primary literature
and reference code/tests. Existing acquired material can be reused; acquire and
manifest missing sources when the unit exposes a real research gap. Use what is
read to choose or challenge mechanisms and direct oracles, then write/refine the
subplan, demonstrate the meaningful red, implement, obtain green, and integrate
independent concrete review findings. Record the useful design consequences and
rejected alternatives with source locations. A bibliography or a research summary
alone does not establish that the reference mechanisms were used. Source study
does not adopt dependencies or execute acquired agents. Specific operator steering
continues to defer mutations and an additional bootstrap plan-review gate.

configurable limitations. The harness supplies the orchestration operation instead

waves: station is a background participant admitted from feeds/triggers; campaign
